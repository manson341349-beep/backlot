# Backlot 片场 v1.4.1

> 作者：Manson AIGC
> 许可：CC BY 4.0（可自由转发、修改、商用，须保留上面这行署名）
> 版本：v1.4.1（2026-11-20），更新记录见 `CHANGELOG.md`

## 一、它在整条流程里的位置

```
拿到剧本 → 拆分镜 → 【搭场景：本技能】 → 出镜头（视频 / 图片）
```

- 剧本、分镜这两步在本技能之外，用你自己的方法或你已有的技能做，本技能不规定怎么做。
- 本技能只管"场景"：空间、建筑、固定陈设、光源。角色、服装、道具设计、逐镜视频提示词都不归它管，用你已有的技能做。
- 本技能的产出是一套场景参考图和一张「角度 → 场景图」对照表，给后面出镜头时挂参考图用。

## 二、为什么要这样做

只靠提示词出同一个场景的不同角度，每张都会"像但不是同一个地方"：门换了位置、灯多了几盏、桌子变了方向。原因是**提示词控制不了空间布局**，参考图又只会把它自己的构图带过来。

所以本技能把两件事拆开管：

| 管什么 | 靠什么 |
|---|---|
| 材质、做工、色调、光的质感 | **母图**（一张定好的场景图） |
| 空间布局、机位、构图、物件位置和数量 | **Blender 白模**的机位渲染图 |

每张派生图同时挂这两张参考图，生成出来的角度才对得上同一个空间。

## 三、开工前先确认三件事

1. **用哪个生图模型**，要支持同时挂 2 张参考图（见 `references/model-notes.md`）。
2. **能不能跑 Blender**：智能体自己能跑命令行 Blender 的，走 A 档；用户自己会开 Blender 的，走 B 档；都不行的，走 C 档草图兜底（见下面第六节）。
3. **生成要花钱的，先提醒**：真正提交生成前说一声用哪个模型、出几张，这一步会花钱或积分。价格不用每次都报，用户问了再报。用户已经说过可以直接出的，不用每张都停下来等回复。默认一次只出 1 张，看过没问题再出下一张。
   **不花钱的修正自己做完**：改白模、挪相机、重渲、叠图对齐、改提示词卡，都不用停下来问用户，做完、对齐了再交。只有改已经定版的东西、剧情上的取舍才问；花钱的事照上一条提醒一句（先看 `references/pitfalls.md` 第 3 条）。

用户已经说过的就不重复问。

## 四、七步流程

### 第 1 步 · 列角度清单

从用户手上的分镜里，挑出这个场景要拍哪几个角度。分镜是什么格式都行：表格、文字分镜、镜头单、一句话描述。没有分镜的，让用户直接说要哪几个角度。

做成一张表：

| 角度代号 | 站在哪、看向哪 | 画面里必须有什么 | 用在哪些镜头 |
|---|---|---|---|
| A | 门口往北看 | 办公桌、办公椅、三扇窗、两盏吊灯 | 1、3、7 |
| B | 窗边往南看（A 的反打） | 门、门边衣帽架、书柜、访客椅 | 2、4 |
| 俯 | 正上方往下看 | 全部家具的位置 | 内部核对用，不出图 |

规则：
- 同一个方向、只是景别不同的镜头，合成一个角度，近景从全景里裁或用全景当参考。
- 用户没给分镜也没说角度时，按最小一套给：一个最能看清结构的主角度、一个它的反打、一张俯视布局。并写明为什么选这几个。
- 两个角度机位要差得够大。只是多一块前景遮挡、其余几乎一样的，算重复，合并掉。

### 第 2 步 · 写场景设定卡

后面每一步都以这张卡为准。模板和完整例子见 `references/scene-card.md`。卡里要有：

1. **一句话定位**：什么地方、什么年代、什么时间、什么天气、新旧程度。
2. **坐标系**：定一个原点，X 往东、Y 往北、Z 往上，单位米。
3. **尺寸**：按现实里同类建筑的真实尺寸定（一间老式办公室大约 5×4 米、层高 3 米上下）。**不要拿分镜里人物之间的距离去倒推房间大小**，那样房间会被压得很小。
4. **构件表**：墙、门窗、家具、固定陈设，每样写位置、尺寸、朝向；门窗写开着还是关着，按剧情这一场的状态定。
5. **光源**：哪几个真实光源（窗、吊灯、台灯、路灯），各在哪、什么颜色、几盏。分开写"固定光源"（属于场景）和"事件光"（车灯、手电，跟镜头走，不进场景图）。
6. **必须有 / 不能出现**：比如"不能出现任何可读文字"。
7. **角度清单**：第 1 步那张表。

### 第 3 步 · 出母图

母图只有一张，管材质、做工、色调和光的质感。写法见 `references/mother-image.md`。

- 选一个能看清整个空间结构的角度，通常是略俯视或 3/4 角度，能同时看到地面、两面以上的墙和主要家具。
- 只放场景里固定的东西。还没设计好的道具、文件，母图里留空，等出镜头时再加，不要让模型自己发明。
- 写明"画面里没有任何可读文字、标牌、标签"，不然模型会自己加假字。摆满商品的货架、书架这类场景，这句压不住小包装上的假字（`references/pitfalls.md` 第 56 条）。
- 提醒一句要出图了 → 出 1 张 → 自检（自检表见 `references/mother-image.md`）。
- **母图定版之前，不出任何派生图**，因为所有派生图都要拿它当参考（先看 `references/pitfalls.md` 第 1 条）。
- 母图和设定卡在结构上对不上（比如母图里门的位置和卡上不同），而用户接受了这张母图：**以母图为准**，把设定卡升一版（比如 v1 → v2），旧版留着。灯的数量、门的开关、剧情状态仍按设定卡和剧情走，不跟母图。母图和卡差得很多是常态，不是出错（先看 `references/pitfalls.md` 第 2 条）。

### 第 4 步 · 搭 Blender 白模

白模是整套方法的核心：它是唯一能精确控制构图的东西。三档做法见 `references/blender-whitebox.md`，A 档可以直接用 `scripts/whitebox_template.py` 改。

> **先母图还是先白模**：也可以先搭一个简陋白模，把门窗、家具、出入口的布局理清楚，再去出母图，这样不算错。但推荐先出母图：母图定下整个场景长什么样，模型出母图时也不会严格照白模的布局来，白模最后还是要照母图对齐（下面第 1 条），先搭的那一版多半要返工。不管哪个顺序，派生图都要等母图定版以后才出。

1. **照母图搭**：先按母图把空间搭出来，在母图那个机位放一台相机，把白模渲染图和母图叠在一起看（`scripts/overlay.py`），墙角、门框、桌子对齐了再往下走。先看 `references/pitfalls.md` 第 2、3、17、19、46 条：
   - 反推母图是站在哪、用多少焦距拍的，可以用 `scripts/solve_camera.py`：在母图上量几个墙角和一样真实尺寸已知的东西（比如门宽），它算出相机位置、焦距和房间尺寸。适用于看得到一面远墙的盒子房间；算出来的是初值，搭好后还要叠图手调。
   - 为了凑尺寸补上去的结构（接墙、填缝、加长）单独列出来，在母图机位用描边叠图专门对一遍（第 46 条）。
   - 对不上就自己改白模和相机，改一轮叠一次，全部对齐了再交，不要停下来问用户"母图定不定版、白模要不要改"。
   - 判断结构、量偏差用描边叠图（`python3 scripts/overlay.py 母图 白模图 输出.png --edge`），一处处量墙角、门框、窗框、桌角差多少像素，写成残差表交出去；50% 半透明叠图只看整体偏没偏。
   - 焦距在一段范围内都能对上的，把范围写进设定卡，看不到的方向当成没定。
2. **每个要出的派生角度都要搭相机、出渲染图**，哪怕那个角度看起来和母图差不多。没有白模的角度，生成出来会照搬母图的构图。每台相机在脚本的 `MUST` 里列出它必须完整拍到什么，投影检查只查这几样。
3. **出一张正交俯视布局图**，可以放人物占位圆柱，给用户和分镜核对站位。
4. **每张渲染图出之前检查**：
   - 天花板在，窗外没有多出来的建筑，墙上没有莫名的阴影条。
   - 卡上点名的物件（灯头、门顶、栏杆两端）完整在画面里，没有被画框切掉；被切掉就放宽这台相机重渲。
   - 有腿的家具要有腿，而且腿着地。
   - 人物占位没有挡住这个角度必须看到的东西。
   - 21:9 这类宽画幅上下很窄，按宽度选的焦距可能切掉高处的灯和门顶，要试渲一张确认。
   - 母图里看不到、没定的墙面不进画面：模板脚本的"未定墙面检查"报 0 才算过（第 16、52 条）；室内再看"露底检查"，画面不能露到房间外面。只转镜头躲不开的，换站位；非拍到那面墙不可的，先出一张补定图把它定下来（第 57 条）。
   - 每张派生白模自己先看一眼：不看提示词，认不认得出站在哪、朝哪看。画面里要带上地面线、吊顶线或墙角，别被近处一件东西占掉大半；房间小、退不开的，把相机身后那面墙隐藏，站到墙外去（第 53 条）。
   - 白模一律用灰、相邻体块深浅拉开，不用带颜色的块（第 54 条）；前后有好几层体块的，另出一张分色版给人审看，不挂给模型（第 47 条）。
   - 墙面、地面放大看，没有方块拼接留下的线和缝（第 14 条）；贴墙的东西没有穿进墙里（第 15 条）。
   - 挂给模型的渲染图整张放大看，亮斑、杂点先在副本上清掉（第 18 条）。
5. **两个相反方向的角度（正反打）要几何上互相对得上**：A 背后的墙就是 B 看到的墙。一个白模服务不了两个互相矛盾的方向，矛盾时先回去改设定卡。
6. **室外和有楼层的场景**多做几件事：室外要铺够大的地面、两头都搭东西、远处用粗体块，并核对每台相机的地平线高度；有楼层的除了平面再出一张剖面看高低。做法见 `references/blender-whitebox.md` 和示例二、示例三。

### 第 5 步 · 出派生图

每张派生图挂两张参考图，写法和提示词卡模板见 `references/derive-prompt.md`：

- **参考图 1**：母图（或已经定版的派生图），只管材质和光。拍到母图里没有的那面墙时，挂给那面墙出的补定图（第 57 条）。
- **参考图 2**：这个角度的白模渲染图，只管构图和布局。

提示词要点：
- 开头写清两张参考图各管什么，并写明"取景范围、每件东西的位置和大小严格按参考图 2，不要拉远、不要平移"（第 53 条）。
- 白模这个角度里没有的东西，提示词里一个字都不提，包括交代光源的句子（写"光从窗户照进来"，窗就会被画进来）；光只写落在画面里的样子（第 48 条）。
- **数量和形状写死**："天花板正好两盏吊灯""椅子四条腿着地""窗是三扇竖窗"。
- 物件照母图里实际的样子写（放大看过的灯型、灯罩朝向），不要只照设定卡写，不然会走样。
- 位置用画面里看得见的地标说（"在书柜左边、贴着墙角"），不要用"离我们近"这种机位说法。
- 每个设备、屏幕、牌子都写明"上面没有可读文字"。
- 这一场如果在剧情变化之后（灯被打碎、桌子被掀翻），把变化后的状态写进去，并压掉母图里和它矛盾的东西。
- 每张卡自己写自己的场景描述，不要从别的角度的卡里整段复制；别的卡里出过问题的颜色、物件，复制过来会被生成回来。
- **写卡前做两件事**（先看 `references/pitfalls.md` 第 22、23 条）：
  1. 打开这个角度的白模图，一件件写"在画面左边 / 右边"，再用"贴着西墙"这类地标定死。反打方向左右本来就是反的；机位改过就重写，不照抄旧卡。
  2. 放大看母图，列一张"母图里看得见的东西"清单（窗上的百叶、开关盒、明线、桌上的小东西），一件件定：固定陈设写进提示词，没设计的道具在卡上写明"清空"。
- 机位焦距尽量在 20 毫米以上，超广角的透视模型会拉平（第 25 条）；光只把主光写清，细的补光留到出镜头时写（第 26 条）。
- 提醒一句要出图了 → 一次出 1 张。

### 第 6 步 · 自检和返修

自检清单和返修办法见 `references/qa-and-repair.md`。核心几条：

- **放大看，不只看全图**：按画面左右两半分别数关键物件的数量；看形状（椅子腿、靠背、灯头）；门扇、窗扇和门框、地面的接缝放大 2 倍看，接缝不对会让门看起来是开着的或飘着的。
- **暗处提亮看**：暗的门缝、门头，把那块提亮 2～2.5 倍、放大 2 倍再看，正常亮度下看不出来。
- **把成图和白模渲染图叠起来比**：50% 叠图看整体偏没偏，描边叠图（`--edge`）量每处偏多少（第 19 条）。
- **先找原因再返修**：
  - 结构错、缺东西、物件位置不对 → 几乎都是白模的问题（白模里少了椅子腿，成图里椅子就悬空）。改白模、重渲，再重出。改提示词挪不动机位。
  - 小毛病（多一盏灯、一块玻璃颜色不对、一个杂点）→ 在副本上局部修图，只改圈出的区域，原图不动，修完用像素对比确认圈外一个像素都没变。不重出。
- 多出来的东西，想一下它按空间会连带出什么，连带的对不上就是穿帮（第 49 条）；说"没有某样东西"之前先把那块放大看（第 50 条）；和卡不一致的先对母图，母图本来就是这样的，改卡不改图（第 51 条）。
- 自检结果（数了什么、数出多少、哪里和白模对不上）写进这张图的自检记录。

### 第 7 步 · 定版和交付

- 用户说"可以 / 定版"之后才算定版。
- 文件命名：`场景名_角度代号_方向_定版.png`，比如 `老办公室_A_门口往北_定版.png`。没定版的带版本号：`老办公室_A_门口往北_v2.png`。
- 写一份定版记录：每张定版图的文件名、用的哪版设定卡和白模、有什么使用条件（比如"这张窗帘是拉上的，只能用在夜戏"）。被替换的旧图标"不用"。
- **交出「角度 → 场景图」对照表**，给用户自己的分镜或视频提示词技能直接挂参考图：

| 角度 | 定版文件 | 站在哪看向哪 | 画面里有 | 用在哪些镜头 | 使用条件 |
|---|---|---|---|---|---|
| A | 老办公室_A_门口往北_定版.png | 南墙门口往北看向窗 | 办公桌、办公椅、三扇窗、吊灯 ×2 | 1、3、7 | 只用于夜戏（窗外是夜景） |

## 五、改已定版的场景

已经定版的图沿用，只补缺口。要改已定版的东西（换家具、改灯），先跟用户说清为什么改、改了会影响哪些已经出好的镜头，用户同意再动。几何改了就把旧设定卡和旧渲染图归档，新开一个版本，不要覆盖旧结果，不然新旧会混在一起。

**只换一样东西的样子**（换灯款、换椅子、换窗帘颜色）：不整张重出，也不先动白模。先在母图上把那一块裁出来、只重画那样东西、用 `scripts/patch_back.py` 贴回，块外一个像素不变；位置或大小变了才改白模那一件；已经出好的派生图同样裁块换。光也变了（颜色、亮度、照的方向）的不适用，要整张重出。新道具的光照方向、范围差得明显的，裁块换也管不到房间里的光。步骤、提示词模板、自检和一次完整的实测记录见 `references/prop-swap.md`。

## 六、没有 Blender 怎么办

| 档 | 谁来搭 | 怎么做 |
|---|---|---|
| A 档 | 智能体能跑命令行 Blender | 照设定卡重写 `scripts/whitebox_template.py` 里的房间、构件、相机、出图四段，一条命令出全部渲染图；以后改尺寸只改数字重跑 |
| B 档 | 用户自己开 Blender | 智能体按设定卡写出逐件搭建清单（每个方块的位置和尺寸）和每台相机的参数，用户照着摆 |
| C 档 | 都没有 | 每个角度画一张简单透视线稿，当参考图 2 用；另画一张俯视草图（标尺寸、门窗、家具、机位箭头）只给自己核对位置，不要挂给模型。控制力比白模弱，复杂场景尽量装个 Blender（免费） |

详细步骤见 `references/blender-whitebox.md`。

## 七、常见坑，一边做一边记

见 `references/pitfalls.md`，都是实际做场景时踩过的，按流程阶段分组，每条四栏：现象、原因、修法、以后怎么防。上面每一步里"先看第 N 条"指的就是它的编号。

**每跑一次流程都要记**：碰到 `pitfalls.md` 里没有的新坑，当场按四栏加一条，再在上面对应的步骤里加一句"先看第 N 条"。加法见 `pitfalls.md` 开头「怎么往这里加」：先搜有没有同类，有就补进那条；原因没查清的写"推测"；不写平台名、人名、花费和自己电脑上的文件路径，带这些细节的原始记录另存一份内部日志。

最常见的三个：

1. 成图里椅子悬空、东西数量不对 → 先查白模，不是先改提示词。
2. 派生图照搬了母图的构图 → 这个角度没挂白模渲染图。
3. 成图里冒出看不懂的假字、假标签 → 提示词里没写"没有可读文字"。

## 场景设定卡：模板和例子

设定卡是整个场景的"唯一说法"。母图、白模、每张派生图的提示词，都以它为准。卡改了就升版本号（v1 → v2），旧版留着不删。

### 模板

```markdown
# <场景名> · 场景设定卡 v1

## 一、一句话定位
<什么地方、哪个年代、什么时间、什么天气、新旧程度，一两句>

## 二、坐标系
原点 = <哪个点，比如西南墙角的地面>。X 往东，Y 往北，Z 往上，单位米。

## 三、尺寸依据
<按现实里同类建筑的尺寸定，写一句依据>

## 四、构件表
| 构件 | 位置 / 尺寸（米） | 朝向 / 状态 | 备注 |
|---|---|---|---|
| 墙、门、窗、家具、固定陈设…… | X a～b，Y c～d，高 h | 门开 / 关，按这一场剧情 | |

## 五、光源
固定光源（属于场景，进场景图）：
1. <光源> —— 在哪、什么颜色、几盏
事件光（跟镜头走，不进场景图）：
- <车灯、手电、屏幕光……>

## 六、必须有 / 不能出现
- 必须有：
- 不能出现：任何可读文字、标牌、标签；……

## 七、角度清单
| 角度代号 | 站在哪、看向哪 | 画面里必须有什么 | 用在哪些镜头 |
|---|---|---|---|

母图里看不到、没定的墙面：<比如母图机位拆掉的那面墙。派生机位要避开>

## 八、和剧本、分镜对不上的地方
<写清哪里对不上、为什么，交给负责剧本或分镜的人定。本技能不改剧本和分镜。>
```

### 写卡时的规矩

- **尺寸按真实建筑定**：一间老式办公室大约 5×4 米、层高 3 米上下；一条双车道大约 7 米宽；多层楼的天台通常几十米见方。不要拿分镜里"两人相距三步"去倒推整个场地，场地会被压小。人物站位放不进场地时，在场地里挪人，把间距问题告诉负责分镜的人。
- **门窗状态按剧情**：这一场门是开着还是关着、窗帘拉没拉，按剧本这一场写，白模也照这个搭。
- **灯要数清楚**：几盏、什么样子、在哪。"几盏灯"这种模糊写法，生成时数量一定会跑。
- **还没设计的道具留空**：卡上写"桌面留空，文件在镜头里另加"，不要先编一个。
- **母图定版后回写**：母图和卡在结构上对不上、而母图已经被接受，按母图把卡改成 v2，坐标从母图反推，再用白模叠母图核对。

## 母图：怎么出、怎么自检

母图是整个场景的"样板间照片"：一张图定下材质、做工、新旧、色调和光的质感。后面每张派生图都拿它当参考图 1。

### 选角度

- 要能看清整个空间的结构：地面、至少两面墙、主要家具、门窗、光源都在画面里。
- 挑角度只看一件事：门、窗、主要家具、光源能不能同时进画面。拿老办公室举例：房间只有五米乘四米，我们从东边往西看，左边南墙的门、右边北墙三扇窗、正对面西墙的书柜、中间的桌椅和两盏吊灯，一张图全有。别的空间照这个标准挑，比如院子、街口站高一点往下看，走廊就顺着走廊看到底。
- 房间小、站在墙角看不全：像影棚拍戏那样"拆掉"一面墙，从那面墙外往里看。白模里把那面墙单独放一组、渲染时隐藏就行；提示词照常写"从东边往西看，能看到整个房间"，不用提拆墙。
- 同样的东西（比如两盏吊灯）不要正好排在视线上，不然会前后叠成一个；相机稍微偏一点、斜着看。
- 不用追求好看的构图，母图是给后面当参考用的，看得清最重要。

### 提示词写法

按"从大到小"写，每句都对应画面里看得见的东西：

1. 一句话定位：什么地方、年代、时间、天气。
2. 空间结构：房间多大、门窗在哪面墙、地面和墙面是什么材质。
3. 家具和固定陈设：每件写位置（用画面里的地标说）、材质、新旧、数量。
4. 光源：哪几个光源、各在哪、颜色、数量；光照到哪里、哪里落暗。
5. 质感：真实拍摄的照片质感、色调。
6. 排除：画面里没有人；没有任何可读文字、标牌、标签；不出现 <设定卡"不能出现"里的东西>。

注意：
- **数量写死**："天花板正好两盏碗形吊灯"，不写"几盏灯"。
- **还没设计的道具不写**：桌面空着就写桌面空着。
- **不要写机位术语堆砌**（"广角镜头、35mm、景深"之类大段堆在一起），写画面里有什么就够了；需要俯视、3/4 这类视角，一句话说清即可。
- 画幅按后面出镜头的画幅定（比如 16:9 或 21:9），母图和派生图保持一致。
- **"没有可读文字"有做不到的时候**：摆满商品的货架、书架这类场景，小包装上像字的花纹压不住（`pitfalls.md` 第 56 条）。这句照样写；自检时只查会被看清的大字（招牌、屏幕、贴纸），小字记进使用条件。

### 例子（老式办公室，写给支持中文的模型）

> 九十年代小城一间私人侦探办公室，深夜，窗外下着小雨。从房间东边往西看，能看到整个房间。房间约五米乘四米，水泥地面，墙下半截刷旧绿漆、上半截米白。画面右边是北墙，三扇竖长木框窗，百叶帘拉起，玻璃上挂着雨水，窗外对面楼有几点冷白灯光。正对面西墙靠着一个两米多高的玻璃门木书柜，里面堆着旧卷宗。房间中间一张旧木办公桌，桌面空着，桌子东头一盏绿色灯罩台灯亮着；桌后一把木椅、桌前一把同款木椅，两把椅子都是四条腿着地、有靠背。画面左边是南墙，远端一扇单扇木门关着，门上半截是磨砂玻璃，门边立着衣帽架挂一件风衣；左边近处靠墙一个铁皮四斗文件柜。天花板正好两盏铁皮碗形吊灯，暖黄光往下照，桌面和地面一圈暖光，墙角落暗。真实拍摄的照片质感，暖黄和窗外冷蓝对比。画面里没有人，没有任何可读文字、标牌、日历和屏幕。

### 出图

1. 提醒一句：用哪个模型、出 1 张，这一步会花钱或积分。价格用户问了再报。
2. 出 1 张。
3. 按下面的表自检，写进自检记录。
4. 不对就改提示词重出（重出前也说一声）；小毛病可以局部修（见 `qa-and-repair.md`）。

### 母图自检表

| 查什么 | 怎么查 | 结果 |
|---|---|---|
| 空间结构看得清 | 地面、两面以上的墙、门窗都在画面里 | |
| 关键物件数量 | 灯、窗、椅子……逐样数，左右两半分开数 | |
| 形状 | 椅子腿、靠背、灯头、门框，放大 2 倍看 | |
| 文字 | 全图放大找假字、假标签、假 logo | |
| 不该出现的东西 | 对照设定卡"不能出现"逐条查 | |
| 多出来的东西 | 卡上没写的门、窗、家具（常见：多一扇门、多一张桌子） | |
| 光源对得上 | 光从卡上写的光源来，没有多出来的灯 | |
| 暗处 | 暗的门缝、角落提亮 2～2.5 倍看有没有怪东西 | |

### 母图定版之后

- 用户接受了母图，它就是这个场景的材质和光的标准，后面不再改它的风格。
- 母图和设定卡在结构上不一样：以母图为准，把卡改成 v2，坐标从母图反推。
- 母图里多出了卡上没有、剧情也不需要的东西（比如一扇多余的门）：可以局部修掉，或者在设定卡里写明"这扇门存在"，二选一，写清楚，不要两边说法不一样。
- **母图没定版之前，不出任何派生图。**

## Blender 白模：三档做法和检查

白模就是用方块和圆柱把场景"摆"出来，不要材质、不要细节，只要尺寸、位置、数量对。每个要出图的角度放一台相机，渲染出来的灰色图就是派生时的参考图 2。

Blender 是免费软件，在 blender.org 下载。本技能的脚本在 Blender 5.2 上实测跑通；只用了最基础的功能，4.x 一般也能跑，但没有实测，跑不通把报错发给智能体改。

### A 档：智能体能跑命令行 Blender

用 `scripts/whitebox_template.py`。它已经搭好了一个"老式办公室"的例子。改成你的场景，要照设定卡重写房间、构件、相机、出图这四段（一般几十行）；这四段以外的工具函数和检查不用动。以后同一个场景改尺寸，只改数字重跑。跑出来是什么样，看 `examples/老办公室/` 里的五张渲染图（母图机位拆掉东墙、A 门口往北、B 窗边往南、椅子检查、俯视布局）。室外场景和有楼层的场景，可以从 `examples/雨夜老街/build_雨夜老街_v1.py`、`examples/两层仓库/build_两层仓库_v1.py` 改起。这两个脚本的搭法和模板一样，但配色和检查还是上一版的：体块带颜色，投影检查不分机位，没有未定墙面检查和露底检查。新做的场景这几样按模板来。

#### 步骤

1. 复制脚本，改名成 `build_<场景名>_v1.py`。
2. 按设定卡重写四段：
   - **房间**：`ROOM` 里的长、宽、高；四面墙各用一个 `box()`，每面墙一整块，不用几块拼（拼缝会渲出竖线）。门、窗做成贴在墙内侧的薄板，不在墙上开洞。
   - **构件**：用 `box()` 加方块（柜、桌面），用 `chair()` 加有腿的椅子，用 `table()` 加有腿的桌子，用 `cyl()` 加圆柱（灯、柱子）。每样放进一个"组"（比如 `家具`、`灯`、`南墙`），方便某个角度把它隐藏。颜色只用灰，相邻的体块深浅拉开。
   - **相机**：`CAMS` 里每个角度一行：相机位置、看向哪个点、焦距。派生机位焦距尽量 20 毫米以上。
   - **检查用的两张表**：`MUST` 里写每台相机必须完整拍到什么（角度清单里"画面里必须有什么"那一栏）；`UNSEEN` 里写母图里看不到、没定的墙面是哪几个组。
   - **出图**：「四、要出哪些图」里每个角度一行 `render(...)`；派生机位加 `check_walls=True`，会自动跑未定墙面检查和露底检查。某个角度要拆墙放相机，就在这一行前后用 `show(南墙=False)`、`show(南墙=True)` 把那面墙隐藏再恢复。
3. 母图对位：把母图路径传进去，脚本会给"母图机位"那台相机挂上母图当背景，并单独出一张对位渲染图。母图机位的位置和焦距先用下面「母图机位怎么反推」里的脚本算一个初值。
4. 跑：
   ```
   blender -b --factory-startup -P build_<场景名>_v1.py -- <输出文件夹> <母图路径(可选)>
   ```
   macOS 上 blender 在 `/Applications/Blender.app/Contents/MacOS/Blender`。
5. 跑完列一下输出文件夹，确认渲染图都在、在对的位置（输出路径写错时会悄悄建出一层多余的子文件夹）。
6. 用 `scripts/overlay.py` 把母图机位的白模渲染图和母图叠在一起看：
   ```
   python3 overlay.py 母图.png 白模_母图机位.png 叠图.png
   python3 overlay.py 母图.png 白模_母图机位.png 描边叠图.png --edge
   ```
   墙角、门框、桌角对不上，就调母图相机的位置、朝向、焦距，或者调构件尺寸，直到对齐。半透明叠图看整体，描边叠图（白模边线描成红线压在母图上）量每处差多少，结构判断以描边叠图为准（见 `pitfalls.md` 第 19 条）。对不上是常态，自己改到对齐再往下走，不用停下来问用户（第 2、3 条）。

#### 母图机位怎么反推

**先用脚本算初值**（适用于"盒子房间"：母图里看得到一面远墙和它两边的墙）：

```
python3 scripts/solve_camera.py --example > 量点.json     先拿一份样例，照着填
python3 scripts/solve_camera.py 量点.json
```

在母图上量这几样的像素坐标填进去：远墙的三四个墙角；左右两条墙顶线上各一个点；一样真实尺寸已知的东西的两头（比如门的左右边框，门宽 0.9 米）。它算出相机离各面墙多远、离地多高、朝向、焦距和房间宽度，直接给出一行可以贴进白模脚本的相机参数；`locate` 里点名的门窗、家具、灯，它换算成场景里的坐标（米）。

- 必须给一样已知尺寸。只靠墙角，焦距定不住：相机拉远、换长焦，墙角照样对得上（`pitfalls.md` 第 17 条）。脚本会按这个尺寸 ±10% 各算一次，报出焦距范围，把范围写进设定卡。
- 已知尺寸不能取在远墙上（远墙上的东西和层高是同一个比例，定不了进深），取在侧墙或地面上：窗宽、地上两件东西的间距。也别取在和相机差不多高的平面上，视线贴着那个面擦过去，量偏一两个像素就差很多。
- 母图是模型画的，透视不严格，残差几十个像素是常事。算出来的只是初值，搭好白模后照样做描边叠图，再手调一两轮。
- 相机身后那面墙母图里看不到，离相机多远是假设（`behind`），写进设定卡的"没定的墙面"。

不是盒子房间（室外、不规则的空间），或者不想用脚本的，手工反推：

- 先猜相机高度：画面里桌面高 0.76 米、门高 2.1 米这类已知尺寸，看它们在画面里的位置，能大概估出相机离地多高。
- 再调朝向：让地面上的直线（墙脚线、地砖缝）在白模和母图里方向一致。
- 最后调焦距：让近处和远处物件的大小比例一致。进深方向最难量准，量不准就在卡里写明"进深按 xx 毫米焦距估计"。

#### 脚本自带的检查

- **投影检查**：脚本会把卡上点名的关键物件（灯、门、桌、椅）投到每台相机的画面里，打印它在画面的什么位置、是否完整在画面内。相机挪过之后必须先刷新场景（脚本里已经做了 `view_layer.update()`），不刷新就算投影，读到的是旧位置，不同相机会算出一模一样的数。
- 投影检查只查 `MUST` 里给这台相机列的东西，最后一行给结论；有没完整入画的，挪相机，或者改 `MUST` 并在卡上写明这个角度不要它。小房间里常常没法全都要，要取舍。
- **未定墙面检查**：母图里看不到、没定的墙面（`UNSEEN`）有没有进派生机位的画面。做法是同一台相机渲两张小图，第二张把那些墙换个颜色，逐像素比差多少，报占画面百分之几，0 才算过。脚本开头先让一台正对着那面墙的相机跑一次"自证"，它报的不是 0，后面的 0 才可信。不要改成"把墙染红、数够红的像素"：渲出来的颜色被灯光压暗，按颜色阈值会漏（`pitfalls.md` 第 52 条）。
- **露底检查**（室内）：画面里有没有露出房间外面的空背景。拆墙放相机、相机退到墙外以后容易从墙头、屋顶外沿露出去，模型会在那里自己画东西。室外场景的天空本来就是背景，不用这项。
- **椅子检查机位**：从斜下方看椅子，确认四条腿都在、都着地。

#### 让白模好认

白模是给模型看的。它认不出这是哪个角度，就不照着画（`pitfalls.md` 第 53 条）。

- **不看提示词，自己先认一遍**：每张派生白模渲出来，看得出站在哪、朝哪看吗？画面里要有地面线、吊顶线或墙角。被近处一件东西占掉大半画面的，换站位。
- **退不开就拆身后的墙**：小房间里站在屋里只能用超广角。把相机身后那面墙隐藏，相机退到墙外，焦距就能用到 20 毫米以上。那面墙在相机身后，本来也不入画。贴着那面墙的家具放进单独一组，一起隐藏，不然它会背对着镜头挡在画面正中。
- **只用灰，深浅拉开**：相邻的体块用不同深浅的灰，前后几层才分得清。不用带颜色的块表示材质，蓝色的"玻璃"会被画成一块蓝板（第 54 条）。
- **前后好几层体块的，另出一张分色版**：每栋（每组）一个颜色，只给人审看，不挂给模型。白模搭错了（两栋房子之间被接成一整面墙）在分色版上最容易看出来（第 46、47 条）。模板脚本没有带这一版：把每个组的 `o.color` 换成不同颜色，再渲一遍就是。

### C 档：没有 Blender

控制力最弱，只适合简单场景。做两样东西，只有第 2 样挂给模型：

1. **俯视草图（只给自己看）**：方格纸或任意画图软件，画墙、门窗、家具的位置，标尺寸，画出每个角度的机位箭头。用来核对位置，**不要挂给出图模型**，模型看到俯视图容易照着画成俯视角度。
2. **每个角度一张透视线稿（这张当参考图 2）**：简单的线框，画出这个角度里墙角线、地面线、主要家具的轮廓和位置。可以手画拍照。

生成时提示词里写"参考图 2 是线稿，只用来确定构图和物件位置"。复杂场景（户外、多层建筑、物件多）建议还是装 Blender。

### 渲染前检查（三档都适用）

| 查什么 | 为什么 |
|---|---|
| 天花板在 | 没有天花板，成图顶上会变成天空或黑洞 |
| 窗外没有多余的建筑 | 白模窗外的东西会被生成成真实建筑 |
| 墙上没有莫名的阴影条 | 会被生成成污渍或结构 |
| 卡上点名的物件完整在画面里 | 被切掉一半的灯，成图里会变形或消失 |
| 有腿的家具有腿、腿着地 | 白模里没腿，成图里一定悬空 |
| 人物占位没挡住必须看到的东西 | 只在俯视图里放人物占位，派生渲染图里隐藏 |
| 宽画幅（21:9）上下够不够 | 按宽度选的焦距可能切掉高处的灯和门顶 |
| 画面边缘 | 母图里有、白模里没有的灯头或光，会从参考图 1 带进来；挪相机避开，或在卡上写明这个角度没有它 |
| 认不认得出站在哪 | 画面里没有地面线、吊顶线、墙角，只剩几块大平面，模型会自己改取景 |
| 只用灰、深浅拉开 | 带颜色的块会被照搬成同色的平板 |
| 母图里没定的墙面、房间外面的空背景不入画 | 这些地方没有依据，模型只能自己编 |

### 正反打和多个方向

- A 看到的墙，就是站在对面往回看时背后的墙。两个方向用同一个白模，几何自然一致。
- 两个方向的需求互相矛盾（A 要求门在左，B 推出来门得在右），一个白模搭不出来，先回去改设定卡，或者把矛盾交给负责分镜的人定，再渲染。
- 拍某个角度时要拆掉一面墙才放得下相机，可以在脚本里把那面墙所在的组隐藏（像影棚里的"活动墙"），并在卡上写明。
- 母图拆掉或没拍到的那面墙，派生机位要避开。四面墙的房间做正反打，两个方向加起来常常非拍到它不可。先出一张专门定这面墙的图（补定图）：挂母图当参考图 1、挂一张正对这面墙的白模当参考图 2，定版后这面墙才算定，把它从脚本的 `UNSEEN` 里拿掉。以后拍到这面墙的角度，参考图 1 改挂补定图。实测过：挂补定图的两张，墙上那扇门的做法、拉手、门边的开关都和补定图一致；只挂母图的两张，门每次都是另一个样子（`pitfalls.md` 第 57 条）。

### 室外场景

例子：`examples/雨夜老街/`。

- **没有天花板，要处理天空**：白模里的天空就是世界背景色，一块平的颜色。每张卡都写清天空是什么样，并写"参考图 2 里的灰色天空只是底色"，不然模型可能照搬一片平灰。
- **地平线高度**：同样是人眼高度平看，地平线落在画面中间附近。几个角度的相机高度差很多，地平线就差很多，剪到一起会跳。脚本可以给每台透视相机算一下地平线在画面里的竖向位置（老街示例脚本里有现成的写法），对一眼就知道。
- **地面铺够大**：铺一块比场景大很多的地（老街示例是 600 米见方），远处和地平线附近不露出"地的边"。
- **两头都要搭**：只搭看过去那一头，反打转过来身后是空的，成图会自己发明。街道、走廊这类长条场景，两头都放东西挡住视线。
- **远处的东西**：两个以上方向都看得到远处，用粗体块（只有长宽高、不做窗户）；远处只在一个方向出现、只要轮廓，可以用一块竖着的背景板，或者干脆只留天空。背景板从斜的角度看会露出是一张平面。
- **尺寸按真实的来**：街宽、人行道宽、店面开间按真实尺寸定，不拿人物走位倒推。走位和尺寸对不上，告诉负责分镜的人。
- **白模里不放的东西**：雨、湿地反光、灯光光晕都不放进白模，写在提示词里。招牌只放一块空板，提示词写"空白"。电线这类细线，剧情要就在白模里用细长方块搭出来，不要就在提示词里写"没有"。
- **投影可以开**：室外开着投影（shadows）能看出路灯、楼的前后关系；有屋顶的室内开投影容易整片压黑、出斑点，可以关掉。

### 有楼层的场景（楼梯、二层走廊、阁楼）

例子：`examples/两层仓库/`。

- **平面加剖面**：平面图看前后左右，剖面看高低。剖面就是拆掉一面墙，用正交相机正对着看过去，放上按真实身高的人物圆柱。只看平面，判断不了"楼上的人能不能看到楼下的人""灯会不会挡在两人中间"。
- **平面里掀掉楼板**：一楼平面要把屋顶和二层楼板隐藏，不然看不到一楼；再用一条细的彩色长条标出楼板前沿的位置。
- **对视点**：楼上楼下两人对话的一组正反打，A 相机放在楼下的人眼睛的位置、看向楼上的人的脸；B 相机放在楼上的人眼睛的位置、看向楼下的人。两台相机在同一条视线两头，仰俯角度由真实高差算出来，正反打自然接得上。
- **楼梯每一级单独搭**：搭成一块斜板，成图会画成斜坡。镂空踏板就只搭踏板，不搭踢面。
- **栏杆按真实间距搭**：扶手、中横杆、立柱都搭出来。细栏杆在仰拍、俯拍里最容易消失或变粗，白模里有，模型才有依据。
- **重叠的面错开 1 厘米**：两个物件有面叠在同一个位置（边梁和楼板、立柱和扶手），渲染出来是一片碎斑，生成时会被当成污渍。把其中一个挪开 1 厘米。

几何改了：把旧的卡、旧脚本、旧渲染图挪进归档文件夹，新脚本叫 `v2`，从头渲染。不要覆盖 v1 的结果。

## 派生图：提示词卡怎么写

每个派生角度写一张提示词卡，卡上记清楚：挂哪两张参考图、顺序、提示词正文、出图后的自检。价格想记就记，不是必填。

### 两张参考图

| 顺序 | 用哪张 | 管什么 | 不管什么 |
|---|---|---|---|
| 参考图 1 | 定版母图（或已定版、和这个角度更接近的派生图） | 材质、做工、新旧、色调、光的质感 | 构图 |
| 参考图 2 | 这个角度的白模渲染图（C 档用线稿） | 构图、机位、物件位置和数量 | 颜色、材质 |

母图修过（局部修图）之后，要用修过的那张当参考图 1，旧的不要再挂。

这个角度拍到了母图里没有的墙面（比如母图机位身后的那面墙）：先给那面墙出一张补定图并定版，这个角度的参考图 1 挂补定图，不挂母图（`pitfalls.md` 第 57 条）。

### 提示词结构

1. **两张参考图各管什么**：一句话写清，并写明取景范围、每件东西的位置和大小严格按参考图 2，不要拉远、不要平移（`pitfalls.md` 第 53 条）。
2. **这个角度看到的空间**：从哪看向哪，画面里从前到后、从左到右有什么，用画面里看得见的地标定位。
3. **物件逐样写**：照母图里实际的样子写（先放大看母图：灯是什么形状、灯罩朝哪、椅背什么样），写数量、写形状。
4. **光**：哪个光源照到哪、哪里亮哪里暗。灯和窗装在房间里是不动的，镜头一转向，同一个光源在画面里的位置就变了，所以每个角度的光都按这个角度重新写。例：老办公室的窗在北墙。A 从门口往北看，窗外冷光在正前方，桌椅朝镜头的一面背光，边缘一圈冷光；B 站窗边往南看，窗到了镜头身后，冷光落在桌椅朝镜头的这一面。B 的提示词不能把 A 里"桌椅背光、边缘发冷"抄过去。
5. **状态**：这一场如果在剧情变化之后，写变化后的状态。
6. **排除**：画面里没有人；每个设备、屏幕、牌子、纸张写明"没有可读文字"；设定卡"不能出现"的东西。

### 写法规矩

- **数量和形状写死**："天花板正好两盏碗形吊灯""两把椅子都是四条腿着地""北墙正好三扇竖窗"。
- **用地标，不用机位词**：写"衣帽架在门的左边、贴着墙角"，不写"衣帽架离我们很近"。
- **每张卡自己写**：不要从别的角度的卡里整段复制。别的卡里出过问题、后来否掉的颜色或物件，一复制过去就会被生成回来；每张卡里正面写出你要的颜色。
- **剧情状态变了，压掉母图里矛盾的东西**：母图是"之前"的状态，比如母图吊灯亮着、这场吊灯被打碎了，就要写"左边那盏吊灯碎了、不亮，只剩台灯的光"。
- **还没设计的道具不写进场景图**：留空，出镜头时再加。
- **白模这个角度里没有的东西，一个字都不提**：包括交代光源的句子。白模里这个角度没有窗，提示词写了"光从窗户照进来"，窗就会被画进画面边上。光只写落在画面里的样子：地上的光斑、门缝透进来的一线光（`pitfalls.md` 第 48 条）。
- **白模里有、成图里一定要有的东西，提示词里也写一遍**；白模和母图冲突时（母图里有三盏灯、卡上和白模是两盏），按卡和白模写，并在卡上记一笔。

### 例子（老式办公室 · 角度 B · 窗户这一头往门口看）

> 参考图 1 只用来确定材质、做工、色调和灯光质感；参考图 2 是这个角度的灰色白模。取景范围、每件家具在画面里的位置、大小和数量都严格按参考图 2，不要拉远、不要平移；参考图 2 的灰色不要照搬，颜色和材质按参考图 1。
> 同一间九十年代私人侦探办公室，深夜。从北边窗户这一头往南看向房门，能看到大半个房间。画面中间偏右是南墙那扇单扇木门，关着，门扇贴着门框，门上半截磨砂玻璃；门右边靠西南墙角立着衣帽架，挂一件深色风衣。画面最右边贴着西墙是两米多高的玻璃门木书柜，只露出靠门的这一头。画面下方近处是旧木办公桌，桌面空着，桌子左头一盏绿色灯罩台灯；桌子靠我们这一侧是办公木椅，椅背朝向我们；桌子靠门那一侧是同款访客木椅，椅面朝向我们，四条腿着地。画面最左边立着一个铁皮四斗文件柜，被画框切掉一半。天花板正好两盏铁皮碗形吊灯，一盏在左上方、一盏在正中上方，暖黄光往下照，门这一侧墙面被照亮，书柜玻璃上有一点灯的反光。真实拍摄的照片质感。画面里没有人；门上的磨砂玻璃、书柜里的卷宗、墙上都没有任何可读文字。

（从北往南看时，西墙在画面右边、东墙在左边。所以书柜、衣帽架写"右边"，文件柜写"左边"，同时用"贴着西墙""靠东墙"这样的地标定死它们。左右写反是派生图最常见的错，写之前对着白模渲染图核一遍。）

### 出图顺序

1. 母图定版之后才出派生图。
2. 每个角度：写卡 → 提醒一句要出图了 → 出 1 张 → 自检 → 下一个角度。
3. 卡改了（换了参考图、改了正文），价格可能变；之前报过价的，提醒一句。

## 自检和返修

### 自检：每张图出来都要做

只看全图是看不出问题的。按下面的表逐项查，结果写进这张图的自检记录。

| 查什么 | 怎么查 |
|---|---|
| 布局 | 成图和白模渲染图 50% 叠在一起看（`scripts/overlay.py`），墙角、门框、家具位置是否对得上；要量偏多少、判断门在哪面墙，加 `--edge` 出描边叠图，一处处量（见 `pitfalls.md` 第 19 条） |
| 数量 | 卡上写死数量的物件，按画面左右两半分开数（"左半两盏、右半零盏"），比整张数更不容易漏 |
| 形状 | 椅子腿、靠背、灯头、栏杆，放大 2 倍看 |
| 接缝 | 门扇、窗扇、闸门和门框、横梁、地面接的地方，放大 2 倍看；门扇上沿比门框低、下沿和旁边对不齐，看起来就是开着的或飘着的，哪怕数量全对 |
| 暗处 | 暗的门缝、门头、角落，提亮 2～2.5 倍再放大 2 倍看，正常亮度下看不出来 |
| 文字 | 全图找假字、假标签、假 logo |
| 多余的东西 | 卡上没写的门、桌子、灯。多出来一样，再想它按这个空间会连带出什么（有窗就该看得见窗下的家具，光也该从那边来）；连带的对不上就是穿帮，不按小毛病处理（`pitfalls.md` 第 49 条） |
| 不该有的东西 | 对照设定卡"不能出现"逐条查 |
| 和母图一致 | 材质、颜色、新旧和母图是同一个地方 |

查过的就写"查过，结果……"；没查的写"没查"，不要笼统写"没问题"。

- **说"没有某样东西"之前先放大看**：缩小的全图里，小而浅的结构会和背景混在一起。没放大看过的，写"没看清"，不写"没有"（第 50 条）。
- **自检同时对母图和卡**：成图和卡不一致、但和母图一致的，是卡写错了，改卡不改图；和母图、卡都不一致的才算毛病（第 51 条）。

### 先找原因，再决定怎么修

| 看到的问题 | 通常的原因 | 怎么修 |
|---|---|---|
| 椅子悬空、桌子没腿 | 白模里就没有腿 | 改白模加腿、重渲，再重出 |
| 物件数量不对、多出一张桌子 | 白模里多了 / 少了，或提示词没写死数量 | 先查白模，再在提示词里写死数量 |
| 构图照搬了母图 | 这个角度没挂白模渲染图 | 搭这个角度的相机、出渲染图、挂上重出 |
| 物件位置不对 | 白模里位置不对，或提示词用了"离我们近"这种机位词 | 改白模；提示词改用地标 |
| 灯头、光从画面边上冒出来 | 母图里有、白模里没有，从参考图 1 带进来的 | 挪相机避开，或卡上写明这里没有 |
| 门看起来是开的 | 门扇和门框的接缝不对 | 检查白模门扇是否贴着门框；提示词写明"门关着，门扇贴着门框" |
| 多一盏灯、一块玻璃颜色不对、一个杂点 | 生成的随机误差 | 局部修图，不重出 |
| 假字、假标签 | 提示词没写"没有可读文字" | 局部修掉，下一张补上这句 |

**改提示词挪不动机位。** 结构和布局的问题，几乎都要回到白模改。

### 局部修图的规矩

小毛病不重出，局部修，省钱也不会丢掉整张图里已经对的部分。

1. **在副本上修**，原图不动，副本文件名带"本地修"和版本号。
2. **只改圈出的区域**。
3. **修完做像素对比**：原图和修过的图逐像素比，确认圈外一个像素都没变（`python3 scripts/pixel_diff.py 原图.png 修过.png x0 y0 x1 y1`）。
4. **量一下修得够不够**：比如要去掉一块偏红的颜色，修之前和修之后各量一次那块区域里偏红像素的占比。
5. **保护光源**：修颜色时按亮度把灯、路灯这些亮的地方排除在外，不要把灯也修暗了。
6. **记下来**：修了哪里、怎么修的、还留下什么痕迹。以后某个镜头正好拍到修过的地方，那个镜头的提示词要写明那里没有那样东西。

有图像软件的用图像软件；智能体能跑 Python 的，可以用 Pillow 按区域修并做像素对比。

### 什么时候要重出

- 布局不对、缺了必须有的东西、结构错（这些改白模后重出）。
- 局部修图修不干净、或者要修的地方太大。

重出前说一声要重出了，这一步会再花一次钱。用户说某张图不好，不等于要重出；问清楚是要重出还是要修。

### 新角度要和已有角度差得够大

新出的角度和已有某个角度只差一块前景遮挡、其余几乎一样，就是重复，作废，不要定版。

### 文件对不对

重新下载的文件在看图软件里看起来没变，可能是软件缓存了旧的预览。比一下文件的校验值（md5），确认文件确实变了或确实没变。

例外：**Blender 的渲染图不能用 md5 比**。每次渲染都会把时间写进 PNG，画面一模一样，md5 也会变。要判断两次渲染是不是一样，逐像素比：`python3 scripts/pixel_diff.py A.png B.png`。

## 换道具：只换场景里一样东西的样子

场景已经定版，只想换其中一样东西的样子（灯换个款、椅子换把老式的、窗帘换个颜色），别的都不动。

**一句话**：先在母图上把那一块裁出来、只重画那样东西、再贴回去；白模只在位置或大小变了时才改；已经出好的派生图同样处理。

这套步骤用老办公室例子实际跑过四张：母图上换两次（一次只换颜色，一次换成样子和大小都变的水晶吊灯），再在两张派生图上换成水晶吊灯。四张都是贴回区外 0 个像素变化、没有接缝。结果和数字见文末「实测记录」，踩到的坑是 `pitfalls.md` 第 39～45 条。

### 0. 先分清是哪一种换法

| 换法 | 例子 | 白模 | 母图 | 派生图 |
|---|---|---|---|---|
| **只换样子** | 灯罩从铁皮换成搪瓷，位置、大小、光都不变 | 不动 | 裁块重画贴回 | 裁块重画贴回 |
| **样子和大小、位置也变** | 碗形吊灯换成更大、挂得更低的水晶吊灯 | 只改这一件，重渲、叠图 | 裁块重画贴回，贴回区要盖住新旧两个轮廓 | 先用新白模定位置，再裁块重画贴回 |
| **光也变** | 暖光碗罩灯换成冷白日光灯管 | 看大小是否变 | 光照到哪里哪里都变，裁块盖不住，**改母图提示词整张重出** | 按新母图重出 |
| **加一样或拿走一样** | 加一盏落地灯、搬走衣帽架 | 加或删这一件 | 加：裁块重画；拿走：局部修图（见 `qa-and-repair.md`） | 同左 |

判断"光变没变"看三样：新东西亮不亮、光的颜色、光往哪照（往下照、往四周散、往上打天花板），有一样明显不同就算光变了。

**裁块换管不到房间里的光**：只有道具本身换了，墙、地、天花板上的光斑都还是原来的。比如碗罩灯只往下照，换成四面散光的水晶灯，按理天花板会亮一圈，裁块换出来天花板几乎不变（`pitfalls.md` 第 45 条）。新旧道具的光差得不多、镜头里看不出来，就按"只换样子"或"样子和大小、位置也变"走，并告诉用户这一点；差得明显，就按"光也变"整张重出。只换样子的，提示词里要写明"光的颜色、亮度不变"。

改的是已经定版的场景，先照 SKILL.md 第五节跟用户说清楚：为什么换、会影响哪些已经出好的图和镜头，用户同意再动。

### 1. 先定新道具的样子

- 样子简单、一句话说得清的（"墨绿搪瓷碗形罩，白内壁"），直接写进提示词。
- 样子讲究、后面很多镜头会拍到特写的，先出一张这个道具的单独参考图，定下来再换。之后每次换都挂这张。
- 写清它和旧的比：大小一样还是更大，挂得一样高还是更低。
- **想让人一眼看出换了，要换轮廓**（形状、大小），不能只换颜色。实测只把铁皮碗罩换成同形状的墨绿搪瓷碗罩，整张图看区别不大；换成轮廓完全不同的水晶吊灯，一眼就看出来。只是想微调颜色的，换颜色就够。

### 2. 在母图上换

**为什么不整张图拿去改**：整张图交给模型改，它往往会把整张都重画一遍，桌子、窗、光跟着变（`model-notes.md` 里 GPT Image 那条）。只给它一小块，它能改的就只有这一小块；贴回时再用蒙版卡住，块外一个像素都不变。

1. **裁块**：把道具连同周围一圈裁出来，外扩约道具大小的 20%～30%，带上一点它照亮的墙或天花板，给模型看清环境。
   - 新道具更大、挂得更低的，裁块要按新道具的大小留地方，往下一直带到新道具会垂到的高度（实测母图换水晶灯时，裁块从 600×450 放到 800×600，下边带到书柜顶）。
   - 裁块按模型支持的画幅比例裁（4:3、1:1、16:9、21:9 这类），记下裁块在原图里的坐标。
   - 一块里有两三件同样的道具，可以一起裁，一次换完。
2. **重画**：参考图 1 挂这块裁块。要挂新道具参考图的，挂成参考图 2。提示词照这个顺序写：
   - 第一句：参考图 1 是什么地方的局部、里面有几件要换的东西。
   - 只换什么、换成什么样（材质、颜色、新旧、结构）。
   - 不变的：吊点或支点、朝向、吊线支架这类连接件；只换样子的，再加位置、大小、光的颜色和亮度。
   - 大小或位置变了的：写新的大小和高度。用图里现成的东西当刻度写（"球底垂到窗框顶边上方一点"），比写倍数准一些，但近处的大件还是常常挂高（`pitfalls.md` 第 43、44 条）。
   - 新道具比旧的小或形状不同的，加一句"原来那件的位置露出后面的天花板和墙"，不然模型会留着旧道具的影子。
   - 其余照参考图 1 原样，构图不变，不加别的东西；没有文字。
   - 画幅和裁块一样。尺寸档选输出不小于裁块的那一档；输出比裁块大会被缩回去，比裁块小会被放大（实测有一张放大了约 1.1 倍贴回，没看出接缝）。

   模板（换自己的东西）：

   ```
   参考图 1 是一间[什么地方]的局部，[位置]有[几件][旧道具]。把这[几件][旧道具]整个换成[新道具]，[吊点 / 支点]不变：[每件在哪]。
   每件是[新道具的结构、材质、颜色、新旧]。[大小、高度：用图里的东西当刻度写]。
   [光的颜色和亮度照参考图 1 / 和参考图 1 差不多]。原来[旧道具]的位置露出后面的[天花板和墙]。
   [周围的东西]和画面其余部分照参考图 1 原样，构图不变，不加别的东西。真实拍摄的照片质感，[时间、室内外]，没有任何文字。
   ```
3. **贴回**：`python3 scripts/patch_back.py 原图.png 重画结果.png X0 Y0 X1 Y1 输出.png --area …`
   - `--area` 是贴回区：每件道具画一个框，框必须在裁块里面。圆东西可以加 `--ellipse`。
   - **贴回区拿到重画结果之后再定**：先把重画结果缩回裁块大小、和裁块逐像素比，算出每件道具实际变了的范围，再往外扩至少羽化宽度的 1.5 倍（默认羽化 12 → 外扩 18 像素以上）。新道具常比旧的大几个像素，按旧道具提前画的框会把新边缘压进羽化带（`pitfalls.md` 第 39 条）。大小变了的，框要同时盖住新道具和旧道具的轮廓，旧道具才不会留残影。
   - **只贴道具**：差异图里道具以外的改动（模型顺手改的天花板阴影、窗玻璃、旁边的家具）不要贴。贴回区按每件道具的新旧轮廓分别画框，不按差异总框（`pitfalls.md` 第 41 条）。实测四张里有三张模型都顺手改了别处。
   - 一件道具的框会碰到模型顺手改动的地方（比如吊灯下面的水晶球垂到百叶窗旁边），把这件拆成几个框（灯身一个、下垂的球一个）。
   - 只有贴回区里换成新内容，边缘羽化过渡；贴回区外一律用原图。
   - 脚本会报两个数：贴回区外变了多少像素（必须是 0）；贴回区外圈一条环带里，重画结果和原图差多少（0～255 的平均差）。实测四张这个数在 0.5～2.8 之间，都没有接缝；明显比这个大，说明模型把整块的颜色或位置也挪了，先看接缝预览再决定。
4. **看接缝**：打开脚本存的接缝预览（裁块放大 2 倍，贴回区描红），沿着红框看有没有颜色断层、吊线断开、墙角线错开、旧道具残影。暗处提亮 2 倍再看一遍。
5. **再确认一次**：`python3 scripts/pixel_diff.py 原图.png 输出.png x0 y0 x1 y1`（框取所有贴回区的外包框），框外必须是 0。
6. 合格就是母图的新版本（比如 v1 → v2）。旧母图归档，不覆盖。同一个场景试几种新道具的，每种开一个版本号，都从原版母图换，不在上一种的结果上叠着改。

### 3. 白模

- 位置、大小、高度都没变：白模不动。
- 变了：只改这一件构件，别的不碰；重渲所有拍得到它的角度；在母图机位和新母图叠图，描边叠图量这一件的偏差。新尺寸先按图上比例估个初值，再按描边叠图的偏差调一轮（`pitfalls.md` 第 42 条）。实测水晶吊灯调了一轮就对上了。
- 设定卡升一版，构件表里改这一件的样子（和尺寸），写一行"某月某日起换成 xx"。

### 4. 派生图

- **已经出好、定版的派生图**：每张照第 2 步同样裁块、重画、贴回，不整张重出（整张重出，之前对好的小物件可能又丢）。参考图 1 挂这张派生图自己的裁块，参考图 2 挂新母图里裁出来的新道具（管样子）。提示词写明"样子、颜色和做工照参考图 2"、"朝向和透视照参考图 1 的视角"，因为每个角度看道具的方向不一样。
- **道具大小或位置变了的**：先看新白模在这个角度的渲染图，定新道具在派生图里大概在哪、多大，再按这个范围裁块（新道具要整个落在裁块里，四周留余量）。派生图的机位和白模渲染常常对不上几十个像素，不要直接拿白模坐标用：量出新旧白模里这件道具的框，算出变大多少、往哪挪了多少，再套到派生图里旧道具的框上，得到预期位置。
- **几件同样的道具隔得远**：可以用一块宽画幅（21:9 这类）把它们一起裁进来，一次重画；贴回时每件单独画框，中间的墙、窗不贴。
- 贴回后拿新道具的实际框和预期框比：大小、底边高度差多少，写进定版记录。实测两张派生图里，远处那件都基本到位，近处的大件一张大了约 19%、挂高约 75 像素，另一张窄了约 13%、挂高约 60 像素（整图宽 2816）。偏差镜头里看不出来就接受并记下，看得出来再单独重出（`pitfalls.md` 第 43、44 条）。
- **还没出的角度**：参考图 1 直接挂新母图，照常出。
- 一张图里这样东西出现几次就换几次，换完数一遍数量。
- 某个角度里这样东西只露出一小角，看不出新旧的，可以不换，在定版记录里写明。

### 5. 记录

- 定版记录里每张图标清楚用的是新道具还是旧道具；旧图标"不用"或"只用于换道具之前的镜头"。
- 大小或位置变了的，记下每张图里新道具的实际位置（不是提示词里写的预期位置），后面的镜头按实际位置用。
- 已经用旧图做出来的镜头，列出来交给用户决定要不要重做，不要自己默认重做。
- 这次换道具踩到的新坑，按四栏记进 `pitfalls.md`。

- [ ] 贴回区外变了 0 个像素（脚本和 `pixel_diff.py` 都是 0）。
- [ ] 接缝预览沿红框看过，提亮看过，没有断层、断线、错位、旧道具残影。
- [ ] 只贴了道具：差异图里模型顺手改的别处没贴进来。
- [ ] 数量对：换了几件、图里现在有几件。
- [ ] 只换样子的：光的颜色、亮度、照到的范围和原来一样。用测量判断：贴回区里亮部的平均颜色、蓝红比、照亮的宽度，新旧对比（`pitfalls.md` 第 40 条）。

## 各生图模型的注意事项

本技能不绑任何模型和平台。派生图要求模型能**同时挂 2 张参考图**，并且能区分"这张管材质、那张管构图"。

> 说明：本技能的实测主要在 Seedream 上完成；下面其他模型的条目是一般经验，没有逐一实测。模型更新很快，参数和能力以平台当前的说明为准。

### 通用

- 参考图顺序固定：参考图 1 = 母图（材质和光），参考图 2 = 白模渲染图（构图）。提示词第一句写清两张各管什么。
- 中文、英文都能写的模型，用你最顺手的语言写，但一张卡里不要中英混杂地描述同一样东西。
- 每个设备、屏幕、牌子都写"没有可读文字"，几乎所有模型都会在空白表面上自己加假字。
- 数量用数字写死，不用"几盏""一些"。

### 挂两张参考图时常见的毛病和对策

派生图同时挂母图和白模渲染图，下面这些毛病各家模型都可能出现。对策是一般经验，具体效果按你用的模型试 1 张再定。

#### 先把挂法定好

- **顺序固定**：参考图 1 永远是母图，参考图 2 永远是白模渲染图。整个项目不换顺序，提示词也不用每次改。
- **按平台的方式标号**：有的平台在提示词里用 `@图片1`，有的写"图1"或"参考图 1"。用平台认的写法，并和上传顺序一一对应。
- **第一句写分工**：提示词第一句就写"参考图 1 只用来确定材质、做工、色调和灯光质感；参考图 2 是这个角度的灰色白模，构图、位置和数量都按参考图 2，颜色和材质按参考图 1"。放在最后容易被忽略。
- **画幅按卡上写的设**：输出画幅在参数里设好，和白模渲染图一样，不要让模型自己跟着某张参考图走。

#### 常见毛病

| 毛病 | 看起来是什么样 | 先查什么 / 怎么改 |
|---|---|---|
| 灰色带进来 | 整张图发灰、像水泥模型上了点色 | 第一句写"颜色和材质按参考图 1"；正文多写具体材质和颜色（旧绿漆、湿柏油、红砖） |
| 照搬母图构图 | 出来的画面和母图几乎一样，没换角度 | 参考图 2 是不是挂了、是不是这个角度的那张；正文按白模重写画面左右有什么，不要整段复制母图提示词 |
| 两张拼在一起 | 左右并排两块，或者画中画 | 第一句写清两张各管什么、"只出一张完整的画面"；去掉正文里"对比""左边是参考图"这类说法 |
| 白模被照着画 | 墙、家具变成光滑方块，像建筑模型；白模里带颜色的块被画成同色的平板 | 正文写真实材质和做旧程度；写"真实拍摄的照片质感"；白模只用灰，不用带颜色的块（`pitfalls.md` 第 54 条） |
| 灯光跟了白模 | 光从奇怪的方向来，阴影和母图不一样 | 白模渲染关掉投影或只用柔和的灯；正文写光从哪里来（窗、吊灯），按母图的光写 |
| 人物占位变成柱子 | 画面里多出一根圆柱、柱墩 | 派生用的白模渲染图里把人物占位隐藏；人物占位只放在俯视图里 |
| 轮廓线变成线稿 | 物件边上有一圈黑线，像描边插画 | 正文写"真实拍摄的照片质感"；描边太重可以在白模渲染里关掉轮廓线再试 |
| 天空照搬一片平灰 | 室外的天是一块平的底色 | 正文写清天空的样子，并写"参考图 2 里的灰色天空只是底色" |
| 白模里的阴影变成污渍 | 墙上、地上多出深色的块和条 | 白模渲染前检查阴影；重叠面错开 1 厘米；有屋顶的室内可以关掉投影 |
| 母图边上的东西跑进来 | 这个角度本来没有的灯、窗被画了进来 | 正文写"这个角度里有什么"，看不到的东西不写，必要时写"画面里没有 xx" |

### Seedream（即梦图片模型）

- 支持多张参考图，在提示词里可以按"图 1""图 2"指代参考图（具体写法看平台：有的用 `@图片1`，有的用"图1"）。
- 白模渲染图的构图跟得比较好；材质跟母图也比较稳。
- 为防止灰色白模把颜色也带进来（画面整体发灰），提示词里写明"图 2 只用来确定构图和位置，颜色和材质按图 1"。

### GPT Image 系列

- 支持多张参考图输入，适合"按这张图的构图、那张图的材质"这类说明。
- 对文字特别敏感，会主动在牌子、屏幕上写字，排除可读文字这句一定要写。
- 改图（编辑）时容易把整张图都重新画一遍，局部小毛病更适合用本地修图，不要用整图编辑去修。

### Nano Banana 系列

- 支持多张参考图，擅长保持参考图里的物件样子。
- 同样要写清两张参考图的分工，不然容易把两张图"拼"在一起。

### Midjourney

- Midjourney 的参考图主要用来带风格和内容，按白模精确控制构图比较难。
- 适合用来出**母图**；派生图建议换上面能按参考图控制构图的模型。

### 不支持参考图的模型

- 只能用来出母图，派生图做不了。可以把母图交给支持参考图的模型去派生。

## 踩过的坑

都是实际做场景时遇到的，例子已改写成通用场景。每条固定四栏：**现象**（看到了什么）｜**原因**｜**修法**（当时怎么解决的）｜**以后怎么防**。标「实测」的是实际出图时踩到的。条目按阶段分组，编号按加进来的先后往下排，所以同一组里编号不一定连着。

### 怎么往这里加

每跑一次流程，碰到这里没有的新坑，就按四栏加一条，规矩是：

1. 先在本文件里搜两三个短关键词，有同类的就补进那一条，不另开。
2. 放进对应的阶段，接着往下编号；不改已有条目的编号，SKILL.md 里按编号链到这里。
3. 四栏都要写。原因没查清的写"推测：……"，修法是"没修"的写明为什么不修。
4. 写通用说法：不写平台名、项目名、人名、花了多少钱、自己电脑上的文件路径。原始记录（带这些细节的）另存一份内部日志，这里只放提炼过的。
5. 在 SKILL.md 对应的步骤里加一句"先看第 N 条"。

### 一、流程顺序

| # | 现象 | 原因 | 修法 | 以后怎么防 |
|---|---|---|---|---|
| 1 | 拿一张派生提示词卡直接去出图，母图还没出（实测） | 单拿出来的派生卡看起来是完整的，智能体不知道它要先有母图 | 停下，先出母图、定版，再回来出派生图 | 每张派生卡第一行写「先出母图并定版，没有母图不要用这张卡」；出派生图前确认参考图 1 是定版母图 |
| 2 | 母图出来后和白模、设定卡对不上：房间更深，灯和窗的位置不同，门换到了另一面墙（实测：房间长度从 5 米变成约 9.8 米，门从南墙跑到西墙南端） | 模型出母图时不会严格照白模和设定卡的布局，文字和参考图只能约束到"大致像" | 用户接受母图后以母图为准：白模照母图一件件改（房间尺寸、门窗、灯、家具），在母图机位叠图对齐；设定卡按母图反推坐标升一版（v1 → v2），旧版留着。灯的数量、门开着关着这类剧情状态仍按卡 | 推荐先出母图再搭白模；先搭了白模的，默认它要照母图返工 |
| 3 | 白模和母图对不上，智能体停下来问用户"母图定不定版、白模要不要改"，结果用户自己发现问题、催着改（实测） | 把不花钱、可以撤回的修正也当成要用户拍板的事 | 默认用户已经接受的母图就是定版，自己改白模、改相机、重渲、反复叠图，全部对齐了再交，交的时候附叠图和每处还差多少；母图有明显结构问题、用户可能想重出的，交的时候一并说，不因此停工 | 只有花钱（出图、重出）、改已经定版的东西、剧情上的取舍才问用户；流程里写明了下一步的，直接做 |

### 二、母图

| # | 现象 | 原因 | 修法 | 以后怎么防 |
|---|---|---|---|---|
| 4 | 母图自带一扇卡上没有的门，剧情不需要，后面每个角度都想把它带进来 | 模型自己加了结构 | 局部修图把门去掉，出一版"去门版"当参考图 1 | 要么修掉，要么在卡上写明它存在，两边说法必须一致 |
| 5 | 母图提示词写了"桌上有文件"，结果每张派生图上的文件都不一样 | 道具还没设计，模型每次自己发明 | 场景图里桌面留空 | 没设计的道具不进场景图；母图里已经画出来的小东西怎么处理，见第 23 条 |
| 56 | 摆满商品的货架、书架这类场景，提示词写了"没有任何可读文字"，成图里包装上还是一片片像字的花纹，屏幕上有界面，玻璃门上多出一张贴纸（实测，母图和三张派生图都这样） | 模型画成堆的包装、书脊时会带上像字的纹样，一句排除压不住 | 没修：当场景参考够用，镜头里看不清这些小字 | 这类场景别把"没有可读文字"当成一定做得到的要求：自检只查会被看清的大字（招牌、屏幕、贴纸），小包装上的假字记进使用条件；镜头要推近到货架的，那个镜头单独处理 |

### 三、白模

| # | 现象 | 原因 | 修法 | 以后怎么防 |
|---|---|---|---|---|
| 6 | 成图里一把椅子像飘在地上 | 白模里椅子只有座板和靠背，没搭腿。白模里没有的结构，成图里一定没有 | 白模搭四条腿、重渲，再重出 | 渲染前查有腿的家具都有腿、腿着地 |

| 8 | 母图前景有一张阅读桌，对位时照搬进白模，到另一个角度它挡在画面里 | 对位用的东西和场景本身的东西混在同一个组 | 隐藏它，重渲 | 对位用的东西放进单独一个组，派生时隐藏 |
| 9 | 挪了相机再算物件在画面里的位置，两台相机算出一样的数 | 挪相机后没刷新场景，读到的是旧位置 | 先 `bpy.context.view_layer.update()` 再算 | 模板脚本里已经写好；自己写脚本的照做 |
| 10 | 21:9 画面里吊灯只剩半截，成图里灯变形 | 按宽度选的焦距，上下太窄 | 放宽这台相机重渲 | 宽画幅先试渲一张，确认点名物件完整在画面里 |
| 11 | 天台只有十几米见方，看着像阳台 | 用分镜里"两人相距几步"去倒推场地 | 按真实建筑尺寸重定场地 | 场地按真实建筑尺寸定，人物在场地里挪 |

| 13 | 以为渲染失败，其实图在 | 渲染图写进了一层多出来的子文件夹 | 找到图，改正输出路径 | 每次渲染后列一下输出文件夹 |

| 16 | 派生角度画面边上露出一截墙，这面墙在母图里看不到，长什么样、离多远都没定，出图只能靠模型自己补（实测） | 选机位时只查了"要的东西都在画面里"，没查"不该进的东西不在画面里"。而且原来那个站位只转镜头解决不了：第二盏灯和那个墙角几乎在同一条视线上，灯完整入画，墙就一定入画 | 换站位，不是只转镜头。用两种办法确认那面墙完全不在画面里：① 从相机往画面里每个格点打射线，数打中那面墙的条数；② 把那面墙临时染成纯红再渲一张，数红像素。都是 0 才算过，再用旧机位跑一次，有红像素，证明检查本身有效。代价是新站位切掉了桌子下半截和书柜一半 | 设定卡里标出"母图里看不到、没定的墙面"；每台派生相机既查点名物件完整在画内，也查这些墙面不在画内 |

### 这个示例教什么

- **小房间拆墙放相机**：站在屋里退不开，就把相机身后那面墙放进单独一组，这个角度渲染时隐藏，站到墙外去。母图拆东墙，A 拆南墙，B 拆北墙。站得开，焦距才能用到 20 毫米以上，画面里也才带得上吊顶、地面和墙角。
- **必须有什么要取舍**：这间房只有 5 × 4 米，B 这个角度没法同时装下整面书柜、两盏吊灯，又不拍到东墙、不露到房间外面（自动找过一遍站位，没有一个都满足的）。所以 B 的必须有里去掉了书柜，换成办公桌，并在对照表的使用条件里写明。
- **母图拆掉的那面墙，派生机位不能拍到**：东墙在母图里没出现过，长什么样没定。脚本对 A、B 各跑一次未定墙面检查，都是 0 才算过。
- **门在母图里很窄也照写**：斜着看门只剩一条边，提示词照样写清门在哪、关着，不然模型可能把那面墙画成没有门。
- **反打的左右**：从北往南看，西墙在右边。每张卡写之前对着白模核一遍左右。
- **椅子检查机位**：有腿的家具单独从斜下方渲一张，确认腿都在、都着地。白模里没腿，成图一定悬空。

### 第 1 步 · 角度清单

假设分镜是这样一段：一个人冒雨沿街往北走（顺着街拍），回头看身后（反打），最后横穿马路走进对面一间亮着灯的小店。

### 这个示例教什么

#### 1. 没有天花板：天空和地平线

- **白模里的天空只是一块平的底色**。不在提示词里写天空，模型可能照搬成一片平平的灰。每张卡都写清天空是什么样（这一例是"低低的暗灰蓝阴云，靠近地平线被城市灯光映亮"），并写"参考图 2 里的灰色天空只是底色"。
- **地平线高度要一致**：同样是人眼高度往前平看，地平线落在画面中间附近（这一例 A、B 都是 0.48）。两个角度的相机高度差很多，地平线就差很多，剪到一起会跳。脚本给每台透视相机打印地平线在画面里的竖向位置（0 是底、1 是顶），对一眼就知道。
- **母图站高一点**：母图是二楼高度（5.5 米），地平线在 0.60，路面多露一些，街道的走向和路灯的排列看得更清楚。
- **地面要铺得够大**：脚本里铺了一块 600 米见方的地，远景和地平线附近不会露出"地的边"。

#### 2. 远处的东西：粗体块还是背景板

| 做法 | 什么时候用 | 这一例 |
|---|---|---|
| 粗体块（只有长宽高的方块，不做窗户和细节） | 两个以上方向都看得到远处；需要远处的楼在不同角度里有合理的透视和遮挡 | 用这个：A 往北、B 往南都看得到远处，南北两头各放了 4～5 个体块 |
| 背景板（一张竖着的平面，或者干脆不放，只留天空） | 远处只在一个方向出现，而且只要个轮廓 | 不用。背景板从斜的角度看会露出是一张平面 |
| 什么都不放 | 远处被近处的楼完全挡住 | C 往东看，对面楼挡死了，远处不用管 |

远景体块**不做细节**：方块上没有窗户，模型会按母图的样子把它画成一栋栋暗轮廓的楼。做了细节反而会被照着画死。

#### 3. 街的两头都要搭

只搭"看过去那一头"，反打转过来身后就是空的，成图会自己发明一条街、一片空地或者天边。这一例南北两头各搭了一排横街对面的楼，A 和 B 的尽头都有东西挡住。

#### 4. 白模里不放、只在提示词里写的东西

- **雨和反光**：白模里没有。每张卡写"路面湿透、有浅积水、倒映灯光"。场景图里的雨丝会被定格成静止的线，后面出视频时由视频提示词加会动的雨更自然（这条是经验建议，本示例没有实测）。
- **招牌**：白模里只有一块板，提示词写"空白的旧招牌板"。不写空白，模型会在每块招牌上编字。
- **电线**：白模里没搭，提示词写"没有电线和电线杆"。白模里没有的细线，每个角度会各画各的，前后对不上；剧情需要电线，就在白模里用细长方块搭出来，再写进卡里。

### 这个示例教什么

#### 1. 楼上楼下怎么对上：对视点

两个人隔着楼层说话，A、B 两台相机都从"人的眼睛"出发：

- A 放在楼下的人眼睛的位置（离地 1.6 米），看向楼上的人的脸（走廊地面 4.2 + 1.6 = 5.8 米）。
- B 放在楼上的人眼睛的位置，看向楼下的人。B 看向的是楼下的人的胸口（1.0 米），这样楼下的人在画面里不会贴着下沿。

两台相机在同一条视线的两头，A 仰多少度、B 就俯差不多多少度（这一例两人水平距离约 6.9 米、高差 4.2 米，A 仰约 31°，B 俯约 35°）。仰俯角度由真实高差算出来，别为了"更有压迫感"把 A 拍成快要垂直的仰拍——那样和 B 接不上，观众会觉得两个人不在同一个空间里。

在平面图里，两个人物占位和 A、B 两个机位标记应该在同一条线上；在剖面里，看两人连线上方和中间有没有东西挡着（这一例的工矿灯在连线南边、高度在两人头顶上方，没挡住）。

#### 2. 仰拍、俯拍常出的问题

下面是这类角度常见的问题和写法上的对策（经验总结；本示例没有出图，没有逐条实测）：

| 角度 | 常见问题 | 对策 |
|---|---|---|
| 仰拍 | 屋顶占掉大半个画面，走廊反而很小 | 白模里先调好屋顶占多少；提示词按白模写"画面上方是屋顶"，不写"高耸的屋顶" |
| 仰拍 | 竖线收拢得太厉害，墙和柱子像要倒下来 | 写"墙和栏杆是竖直的，只稍微往上收拢"；焦距别太广 |
| 仰拍 | 走廊底面画成了天花板，看不出是一条悬在半空的走廊 | 写清"走廊前沿一道钢边梁、底面背光、下面有钢柱撑着" |
| 俯拍 | 前景栏杆糊成一片，或者干脆消失 | 写清栏杆在前景、扶手和横杆的走向、立柱一根根排开 |
| 俯拍 | 地面上的东西缩成玩具大小 | 写清东西的真实大小（"边长一米多的大木箱"） |
| 俯拍 | 地面占满画面，看不出是在高处往下看 | 白模里保留一段远处的墙；提示词写"远处是南墙" |
| 都有 | 细栏杆数量和粗细每张不一样 | 白模里栏杆按真实间距搭出来，提示词不写具体根数，写"按参考图 2" |
| 楼梯 | 镂空楼梯画成了实心斜坡，或者一级级的台阶数对不上 | 写"一级一级镂空的钢踏板，能透过缝隙看到后面"；白模里每一级都单独搭 |

#### 3. 平面加剖面

有楼层的场景，平面图（掀掉屋顶和楼板）看前后左右；剖面（拆掉一面墙，正交看过去）看高低。这一例平面里走廊楼板掀掉了，所以用一条黄线标出走廊前沿，看得出楼梯是从哪里接上走廊的。剖面里放两个人物圆柱，按真实身高，一眼就看得出楼上的人比楼下的人高出多少。

#### 4. 画面里看不到的东西不写

母图看得到两盏灯，派生 A、B、C 里一盏都看不到，所以 A、B、C 的卡写"没有亮着的灯"，不写"三盏工矿灯"。写进去了，模型会想办法把灯画进来，构图就跑了。每张卡写之前，对着那张白模和脚本打印的投影检查核一遍：这个角度里有什么，就写什么。

## scripts/whitebox_template.py

```python
# Backlot 片场 v1.4.1 · 白模模板脚本
# 作者：Manson AIGC · 许可 CC BY 4.0（转发、修改请保留这一行署名）
#
# 用法（命令行，不开界面）：
#   blender -b --factory-startup -P whitebox_template.py -- <输出文件夹> [母图路径]
# 也可以在 Blender 里新建一个空白文件，到 Scripting 面板粘贴运行：脚本会先清空这个文件里的东西再搭，
#   所以不要在有你自己作品的文件里跑。输出到 .blend 所在文件夹；文件没保存过，就输出到 主目录/Backlot_白模输出。
#
# 例子场景：九十年代老式办公室，5 × 4 米，层高 3 米（和 references/scene-card.md 的例子一致）。
# 改成你的场景：重写「一、房间」「二、构件」「三、相机」「四、要出哪些图」这四段（墙、构件、相机都要照设定卡重写，
#   不只是改几个数字）；这四段以外的工具函数和检查不用动。
# 坐标：原点 = 西南墙角地面；X 往东，Y 往北，Z 往上；单位米。
import bpy, math, os, sys
from mathutils import Vector
from bpy_extras.object_utils import world_to_camera_view

argv = sys.argv[sys.argv.index("--") + 1:] if "--" in sys.argv else []
OUT = os.path.abspath(argv[0]) if argv else (os.path.dirname(bpy.data.filepath)
                                              or os.path.join(os.path.expanduser("~"), "Backlot_白模输出"))
MOTHER = argv[1] if len(argv) > 1 else ""          # 母图路径，可不填
RENDERS = os.path.join(OUT, "renders"); os.makedirs(RENDERS, exist_ok=True)
NAME = "老办公室_白模_v2"                            # 输出文件名前缀

if bpy.app.background:                             # 命令行：从空白开始
    bpy.ops.wm.read_factory_settings(use_empty=True)
else:                                              # 界面里粘贴运行：只清空当前文件里的物体和组
    for o in list(bpy.data.objects): bpy.data.objects.remove(o, do_unlink=True)
    for c in list(bpy.data.collections): bpy.data.collections.remove(c)
scene = bpy.context.scene
GROUPS = {}

def group(n):
    """每样东西放进一个组，某个角度可以整组隐藏（比如拆掉一面墙放相机）。"""
    if n not in GROUPS:
        c = bpy.data.collections.new(n); scene.collection.children.link(c); GROUPS[n] = c
    return GROUPS[n]

_cube = bpy.data.meshes.new("unit_cube")
_cube.from_pydata([(x, y, z) for x in (-.5, .5) for y in (-.5, .5) for z in (-.5, .5)], [],
                  [(0, 1, 3, 2), (4, 6, 7, 5), (0, 4, 5, 1), (2, 3, 7, 6), (0, 2, 6, 4), (1, 5, 7, 3)])
_cube.update()

def box(n, x0, x1, y0, y1, z0, z1, col, g):
    """方块：给出 X、Y、Z 三个方向的起止坐标。"""
    o = bpy.data.objects.new(n, _cube)
    o.location = ((x0 + x1) / 2, (y0 + y1) / 2, (z0 + z1) / 2)
    o.scale = (abs(x1 - x0), abs(y1 - y0), abs(z1 - z0))
    o.color = (*col, 1); group(g).objects.link(o); return o

def cyl(n, x, y, z0, z1, r, col, g, verts=24):
    """竖直圆柱：灯罩、柱子、人物占位。"""
    m = bpy.data.meshes.new(n + "_mesh")
    pts = [(r * math.cos(2 * math.pi * k / verts), r * math.sin(2 * math.pi * k / verts)) for k in range(verts)]
    vs = [(px, py, -.5) for px, py in pts] + [(px, py, .5) for px, py in pts]
    fs = [tuple(range(verts))[::-1], tuple(range(verts, 2 * verts))]
    fs += [(k, (k + 1) % verts, verts + (k + 1) % verts, verts + k) for k in range(verts)]
    m.from_pydata(vs, [], fs); m.update()
    o = bpy.data.objects.new(n, m); o.location = (x, y, (z0 + z1) / 2); o.scale = (1, 1, z1 - z0)
    o.color = (*col, 1); group(g).objects.link(o); return o

def table(n, cx, cy, w, d, h, col, g, top=.04, leg=.05):
    """有四条腿的桌子：中心 (cx, cy)，宽 w（X 向）、深 d（Y 向）、高 h。"""
    x0, x1, y0, y1 = cx - w / 2, cx + w / 2, cy - d / 2, cy + d / 2
    box(n + "_桌面", x0, x1, y0, y1, h - top, h, col, g)
    for i, (lx, ly) in enumerate([(x0, y0), (x1 - leg, y0), (x0, y1 - leg), (x1 - leg, y1 - leg)]):
        box(f"{n}_腿{i+1}", lx, lx + leg, ly, ly + leg, 0, h - top, col, g)

def chair(n, cx, cy, facing, col, g, seat=.45, size=.46, back=.95, leg=.04):
    """有四条腿、有靠背的椅子。facing = 'N' / 'S' / 'E' / 'W'：坐的人面朝哪边。靠背在反方向。
    座板下面留空、看得见地面；后腿一直通到靠背顶当立柱。"""
    s = size / 2; x0, x1, y0, y1 = cx - s, cx + s, cy - s, cy + s
    box(n + "_座板", x0, x1, y0, y1, seat - .04, seat, col, g)
    back_side = {"N": "S", "S": "N", "E": "W", "W": "E"}[facing]
    corners = {"SW": (x0, y0), "SE": (x1 - leg, y0), "NW": (x0, y1 - leg), "NE": (x1 - leg, y1 - leg)}
    for k, (lx, ly) in corners.items():
        tall = back_side in k
        box(f"{n}_腿_{k}", lx, lx + leg, ly, ly + leg, 0, back if tall else seat - .04, col, g)

    for n in need:

        if not o:
            print(f"  {n}: 【场景里没有这个名字，检查 MUST 里的拼写】"); bad += 1; continue

        print(f"  {n}: 横 {min(xs):.2f}～{max(xs):.2f}  竖 {min(ys):.2f}～{max(ys):.2f}  {state}")

    _small_render(pb, W, Hh)
    for o, c in zip(objs, old): o.color = c
    ia, ib = bpy.data.images.load(pa), bpy.data.images.load(pb)
    a = np.array(ia.pixels[:]).reshape(-1, 4)[:, :3]; b = np.array(ib.pixels[:]).reshape(-1, 4)[:, :3]
    pct = float((np.abs(a - b).max(axis=1) > .03).mean() * 100)
    bpy.data.images.remove(ia); bpy.data.images.remove(ib); os.remove(pa); os.remove(pb)
```

```python
def basis(yaw, pitch):
    """相机自己的坐标：d 往远墙，l 往右，z 往上。yaw 往右转为正，pitch 往下为正。"""
    F = np.array([math.cos(pitch) * math.cos(yaw), math.cos(pitch) * math.sin(yaw), -math.sin(pitch)])
    R = np.array([-math.sin(yaw), math.cos(yaw), 0.0]); U = np.cross(F, R)
    return F, R, U

class Model:
    def __init__(self, cfg):
        self.W, self.Hh = cfg["image"]; self.H = float(cfg["height"]); self.cfg = cfg
    def unpack(self, p):
        return dict(D=math.exp(p[0]), cz=math.exp(p[1]), f=math.exp(p[2]), Lw=p[3], Rw=p[4], yaw=p[5], pitch=p[6])
    def proj(self, q, P):
        F, R, U = basis(q["yaw"], q["pitch"]); d = np.array(P, float) - np.array([0, 0, q["cz"]]); z = d @ F
        z = z if abs(z) > 1e-6 else 1e-6
        return np.array([self.W / 2 + q["f"] * (d @ R) / z, self.Hh / 2 - q["f"] * (d @ U) / z])
    def ray(self, q, u, v, on):
        F, R, U = basis(q["yaw"], q["pitch"]); C = np.array([0, 0, q["cz"]])
        d = F * q["f"] + R * (u - self.W / 2) - U * (v - self.Hh / 2)
        if isinstance(on, dict): axis, val = 2, float(on["height"])
        else: axis, val = {"left_wall": (1, -q["Lw"]), "right_wall": (1, q["Rw"]), "far_wall": (0, q["D"]),
                           "floor": (2, 0.0), "ceiling": (2, self.H)}[on]
        t = (val - C[axis]) / (d[axis] if abs(d[axis]) > 1e-9 else 1e-9)
        return C + t * d
    def corner(self, q, name):
        side, lvl = name.split("_")[1], name.split("_")[2]
        return (q["D"], -q["Lw"] if side == "left" else q["Rw"], self.H if lvl == "top" else 0.0)
    def residual(self, p):
        q = self.unpack(p); r = []; pts = self.cfg.get("points", {})
        for name, uv in pts.items():
            if name.startswith("far_"):
                r += list(self.proj(q, self.corner(q, name)) - np.array(uv, float))
            elif name.endswith("_line"):                      # 点到投影直线的距离
                side, lvl = name.split("_")[0], name.split("_")[1]
                l = -q["Lw"] if side == "left" else q["Rw"]; z = self.H if lvl == "top" else 0.0
                a, b = self.proj(q, (q["D"], l, z)), self.proj(q, (q["D"] * .4, l, z))
                n = np.array([-(b - a)[1], (b - a)[0]]); n = n / (np.linalg.norm(n) + 1e-9)
                r.append(float((np.array(uv, float) - a) @ n))
        for k in self.cfg.get("known_sizes", []):
            a, b = self.ray(q, *k["a"], k["on"]), self.ray(q, *k["b"], k["on"])
            r.append((np.linalg.norm(a - b) - self.scale * k["meters"]) * 300.0)
        return np.array(r, float)
    scale = 1.0

def lm(fun, p, iters=300):
    lam = 1e-2; r = fun(p); c = r @ r
    for _ in range(iters):
        J = np.zeros((len(r), len(p)))
        for i in range(len(p)):
            dp = np.zeros(len(p)); dp[i] = 1e-6 * max(1.0, abs(p[i])); J[:, i] = (fun(p + dp) - r) / dp[i]
        A, g = J.T @ J, J.T @ r; step = None
        while lam < 1e12:
            try: s = np.linalg.solve(A + lam * (np.diag(np.diag(A)) + 1e-9 * np.eye(len(p))), -g)
            except np.linalg.LinAlgError: lam *= 10; continue
            r2 = fun(p + s); c2 = r2 @ r2
            if np.isfinite(c2) and c2 < c: p, r, c, step = p + s, r2, c2, s; lam = max(lam / 3, 1e-9); break
            lam *= 4
        if step is None or np.linalg.norm(step) < 1e-10: break
    return p, r

def solve(m):
    best = None; pts = m.cfg.get("points", {})
    us = [uv[0] for n, uv in pts.items() if n.startswith("far_")]
    for f0 in (.45, .6, .8, 1.1):
        for D0 in (3.0, 6.0, 10.0, 16.0):
            f = f0 * m.W; yaw0 = math.atan((m.W / 2 - (sum(us) / len(us) if us else m.W / 2)) / f)
            p0 = np.array([math.log(D0), math.log(1.6), math.log(f), 2.0, 2.0, yaw0, .08])
            try: p, r = lm(m.residual, p0)
            except Exception: continue
            q = m.unpack(p)
            if q["Lw"] + q["Rw"] <= 0.3: continue           # 左右墙挤在一起，不是真解
            if best is None or r @ r < best[1] @ best[1]: best = (p, r)
    return best

def to_scene(cfg, q, P):
    """相机坐标 (d, l, z) → 场景坐标（原点 = 西南墙角地面，X 往东，Y 往北）。"""
    d, l, z = P; b = float(cfg.get("behind", 1.0)); far = cfg.get("far_wall", "east")
    if far == "east":  return (b + d, q["Rw"] - l, z)
    if far == "west":  return (q["D"] - d, q["Lw"] + l, z)
    if far == "north": return (q["Lw"] + l, b + d, z)
    if far == "south": return (q["Rw"] - l, q["D"] - d, z)
    raise SystemExit("far_wall 只能是 east / west / north / south")

def main():
    if len(sys.argv) < 2: sys.exit("用法：python3 solve_camera.py 量点.json    （样例：python3 solve_camera.py --example）")
    if sys.argv[1] == "--example": print(json.dumps(EXAMPLE, ensure_ascii=False, indent=2)); return
    cfg = json.load(open(sys.argv[1], encoding="utf-8")); m = Model(cfg)
    n_corner = sum(1 for n in cfg.get("points", {}) if n.startswith("far_"))
    if n_corner < 3: sys.exit("至少要量三个远墙的墙角（far_left_top / far_right_top / far_left_bottom / far_right_bottom）")
    if not cfg.get("known_sizes"):
        sys.exit("没有 known_sizes：只靠墙角定不住焦距（pitfalls.md 第 17 条）。量一样真实尺寸已知的东西，比如门宽。")
    if all(k.get("on") == "far_wall" for k in cfg["known_sizes"]):
        sys.exit("known_sizes 全都取在远墙上：远墙上的尺寸和层高是同一个比例，定不了进深。换一样在侧墙或地面上的（窗宽、地上两件东西的间距）。")
    best = solve(m)
    if best is None: sys.exit("没算出来：检查量的点是不是填错了角（左右、上下）")
    p, r = best; q = m.unpack(p); mm = lambda f: f / m.W * 36
    print("=== 残差（像素；几十个像素以内算正常，母图的透视本来就不严格）===")
    i = 0
    for name in cfg.get("points", {}):
        if name.startswith("far_"): print(f"  {name}: 横 {r[i]:+.0f}  竖 {r[i+1]:+.0f}"); i += 2
        else: print(f"  {name}: 离线 {r[i]:+.0f}"); i += 1
    for k in cfg["known_sizes"]: print(f"  {k.get('name', '已知尺寸')}: 差 {r[i] / 300:+.2f} 米"); i += 1
    print("=== 相机和房间（相机自己的坐标）===")
    print(f"  相机离远墙 {q['D']:.2f} 米，离左墙 {q['Lw']:.2f} 米，离右墙 {q['Rw']:.2f} 米，离地 {q['cz']:.2f} 米")
    print(f"  房间宽（左墙到右墙）{q['Lw'] + q['Rw']:.2f} 米；层高按 {m.H} 米")
    print(f"  朝向：比正对远墙往{'右' if q['yaw'] > 0 else '左'}偏 {abs(math.degrees(q['yaw'])):.1f}°，"
          f"往{'下' if q['pitch'] > 0 else '上'}俯仰 {abs(math.degrees(q['pitch'])):.1f}°")
    print(f"  焦距 {mm(q['f']):.1f} 毫米（按 36 毫米宽的画幅）")
    rng = []
    for s in (.9, 1.1):                                        # 已知尺寸 ±10%，看焦距跟着变多少
        m.scale = s; b2 = solve(m)
        if b2: rng.append(mm(m.unpack(b2[0])["f"]))
    m.scale = 1.0
    if len(rng) == 2:
        print(f"  已知尺寸差 ±10% 时，焦距在 {min(rng):.1f}～{max(rng):.1f} 毫米之间都对得上。把这个范围写进设定卡。")
    F, R, U = basis(q["yaw"], q["pitch"]); C = np.array([0, 0, q["cz"]])
    loc = to_scene(cfg, q, C); tgt = to_scene(cfg, q, C + F * 5)
    b = float(cfg.get("behind", 1.0)); far = cfg.get("far_wall", "east")
    length, width = q["D"] + b, q["Lw"] + q["Rw"]
    print(f"=== 换算成场景坐标（原点 = 西南墙角地面；远墙 = {far} 墙；相机身后的墙按 {b} 米假设）===")
    print(f"  房间：东西 {length if far in ('east', 'west') else width:.2f} 米，南北 {width if far in ('east', 'west') else length:.2f} 米")

    if cfg.get("locate"):
        print("=== 点名的位置（场景坐标，米）===")
        for k in cfg["locate"]:
            P = to_scene(cfg, q, m.ray(q, *k["pixel"], k["on"]))
            print(f"  {k['name']}: X={P[0]:.2f}  Y={P[1]:.2f}  Z={P[2]:.2f}")

if __name__ == "__main__":
    main()
```

```python
# Backlot 片场 v1.4.1 · 叠图检查
# 作者：Manson AIGC · 许可 CC BY 4.0
#
# 把成图和白模渲染图叠在一起，看布局对不对得上：
#   母图 vs 母图机位的白模渲染图（对位），或 派生成图 vs 这个角度的白模渲染图（自检）。
# 两种叠法：
#   默认：50% 半透明叠图，看整体偏没偏。
#   --edge：描边叠图，把图B（白模渲染图）的边线描成红线压在图A上。判断结构（门在哪面墙、
#           墙有没有转折）和量偏差用这个，半透明叠图线条混在一起容易看错（见 pitfalls.md 第 19 条）。
# 用法：python3 overlay.py <图A 成图> <图B 白模渲染图> <输出.png> [图A提亮倍数，默认 1.0] [--edge]
#   夜景、暗场景的成图可以把提亮倍数设成 2～2.5，暗处的墙角门框才看得清。
# 需要 Pillow：pip install pillow
import sys
from PIL import Image, ImageEnhance, ImageFilter

args = [x for x in sys.argv[1:] if x != "--edge"]
edge = "--edge" in sys.argv[1:]
if len(args) < 3:
    sys.exit("用法：python3 overlay.py <图A> <图B> <输出.png> [图A提亮倍数] [--edge]")
a = Image.open(args[0]).convert("RGB")
k = float(args[3]) if len(args) > 3 else 1.0
if k != 1.0:
    a = ImageEnhance.Brightness(a).enhance(k)
if edge:
    b = Image.open(args[1]).convert("L").resize(a.size, Image.LANCZOS)
    lines = b.filter(ImageFilter.FIND_EDGES).point(lambda v: 255 if v > 10 else 0)
    lines = lines.filter(ImageFilter.MaxFilter(3))          # 线加粗到约 3 像素，缩小看也看得见
    out = Image.composite(Image.new("RGB", a.size, (255, 40, 40)), a, lines)
else:
    b = Image.open(args[1]).convert("RGB").resize(a.size)
    out = Image.blend(a, b, 0.5)
out.save(args[2])
print("已保存：", args[2])
```

```python
# Backlot 片场 v1.4.1 · 像素对比
# 作者：Manson AIGC · 许可 CC BY 4.0
#
# 两个用处：
#   1. 局部修图后，确认圈外一个像素都没变：python3 pixel_diff.py 原图.png 修过.png [x0 y0 x1 y1]
#      给了圈选框，就分别报告框内、框外变了多少像素；框外应该是 0。
#   2. 判断两张渲染图是不是真的一样（md5 不能用，见 qa-and-repair.md）：python3 pixel_diff.py A.png B.png
# 需要 Pillow：pip install pillow
import sys
from PIL import Image, ImageChops

if len(sys.argv) not in (3, 7):
    sys.exit("用法：python3 pixel_diff.py <图A> <图B> [x0 y0 x1 y1]")
a = Image.open(sys.argv[1]).convert("RGB")
b = Image.open(sys.argv[2]).convert("RGB")
if a.size != b.size:
    sys.exit(f"两张图尺寸不同：{a.size} 和 {b.size}，不能逐像素比")
diff = ImageChops.difference(a, b).convert("L").point(lambda v: 255 if v else 0)
total = sum(1 for v in diff.getdata() if v)

if len(sys.argv) == 7:
    x0, y0, x1, y1 = map(int, sys.argv[3:7])
    inside = sum(1 for v in diff.crop((x0, y0, x1, y1)).getdata() if v)
    print(f"圈选框内变了 {inside} 个像素，框外变了 {total - inside} 个像素", "（框外没动，合格）" if total == inside else "（框外有改动，不合格）")
```

## scripts/patch_back.py

```python
# Backlot 片场 v1.4.1 · 换道具：把重画过的裁块贴回原图
# 作者：Manson AIGC · 许可 CC BY 4.0
#
# 用法见 references/prop-swap.md。流程：从原图裁出道具那一块 → 交给模型只重画道具 →
# 用本脚本把重画结果缩回裁块大小，只在"贴回区"里换上新内容（边缘羽化），贴回区外一个像素都不动。
#
#   python3 patch_back.py 原图.png 重画结果.png X0 Y0 X1 Y1 输出.png \
#       --area x0 y0 x1 y1 [--area ...] [--ellipse] [--feather 12]
#
#   X0 Y0 X1 Y1   当初裁块在原图里的位置（原图坐标）
#   --area        贴回区，原图坐标（右下角不含，和 pixel_diff.py 一样），可以给多个（一块里有两盏灯就给两个）；必须在裁块里面
#   --ellipse     贴回区按椭圆，不按矩形（灯罩、圆桌这类圆东西用）
#   --feather     羽化宽度（像素），默认 12；贴回区要比道具外扩出至少这么多
#
# 跑完会报告：贴回区外变了多少像素（应该是 0）；贴回区外圈一条环带里，重画结果和原图差多少
# （差得多说明模型把整块的颜色或位置也改了，贴回会有接缝，要先看接缝预览图）。
# 需要 Pillow：pip install pillow
import argparse
from PIL import Image, ImageChops, ImageDraw, ImageFilter, ImageStat

ap = argparse.ArgumentParser()
ap.add_argument("orig"); ap.add_argument("patch")
ap.add_argument("x0", type=int); ap.add_argument("y0", type=int)
ap.add_argument("x1", type=int); ap.add_argument("y1", type=int)
ap.add_argument("out")
ap.add_argument("--area", type=int, nargs=4, action="append", required=True)
ap.add_argument("--ellipse", action="store_true")
ap.add_argument("--feather", type=int, default=12)
a = ap.parse_args()

orig = Image.open(a.orig).convert("RGB")
box = (a.x0, a.y0, a.x1, a.y1)
cw, ch = a.x1 - a.x0, a.y1 - a.y0
patch = Image.open(a.patch).convert("RGB")
pw, ph = patch.size
if abs(pw / ph - cw / ch) > 0.02:
    print(f"注意：重画结果比例 {pw}x{ph} 和裁块 {cw}x{ch} 不一样，缩放会变形，先查模型是不是改了画幅")
patch = patch.resize((cw, ch), Image.LANCZOS)

# 贴回区蒙版（裁块坐标）
mask = Image.new("L", (cw, ch), 0)
d = ImageDraw.Draw(mask)
for x0, y0, x1, y1 in a.area:
    if not (a.x0 <= x0 < x1 <= a.x1 and a.y0 <= y0 < y1 <= a.y1):
        raise SystemExit(f"贴回区 {x0,y0,x1,y1} 不在裁块 {box} 里面")
    r = (x0 - a.x0, y0 - a.y0, x1 - a.x0 - 1, y1 - a.y0 - 1)  # 右下角不含，和裁块坐标一致
    (d.ellipse if a.ellipse else d.rectangle)(r, fill=255)
hard = mask.copy()
if a.feather > 0:
    # 先往里收再羽化，保证羽化后不超出给定的贴回区
    mask = mask.filter(ImageFilter.MinFilter(a.feather * 2 + 1 if a.feather * 2 + 1 <= 51 else 51))
    mask = mask.filter(ImageFilter.GaussianBlur(a.feather / 2))
    mask = ImageChops.multiply(mask, hard)

crop = orig.crop(box)
merged = Image.composite(patch, crop, mask)
out = orig.copy(); out.paste(merged, box[:2]); out.save(a.out)

# 自查 1：贴回区外有没有变
diff = ImageChops.difference(orig, out).convert("L").point(lambda v: 255 if v else 0)
full_hard = Image.new("L", orig.size, 0); full_hard.paste(hard, box[:2])
outside = ImageChops.multiply(diff, ImageChops.invert(full_hard))
n_out = sum(1 for v in outside.getdata() if v)
n_in = sum(1 for v in diff.getdata() if v) - n_out
print(f"贴回区里变了 {n_in} 个像素；贴回区外变了 {n_out} 个像素（应该是 0）")

# 自查 2：贴回区外圈 24 像素环带，模型结果和原图差多少（看有没有整体偏色或错位）
ring = hard.filter(ImageFilter.MaxFilter(49))
ring = ImageChops.subtract(ring, hard)
st = ImageStat.Stat(ImageChops.difference(crop, patch).convert("L"), ring)
print(f"贴回区外圈环带：重画结果和原图平均差 {st.mean[0]:.1f}（0–255；超过 8 左右多半有可见接缝，放大看预览）")

# 接缝预览：裁块范围放大 2 倍，贴回区边线描红
prev = merged.resize((cw * 2, ch * 2), Image.LANCZOS)
pd = ImageDraw.Draw(prev)
for x0, y0, x1, y1 in a.area:
    r = [(x0 - a.x0) * 2, (y0 - a.y0) * 2, (x1 - a.x0) * 2, (y1 - a.y0) * 2]
    (pd.ellipse if a.ellipse else pd.rectangle)(r, outline=(255, 0, 0), width=2)
pv = a.out.rsplit(".", 1)[0] + "_接缝预览.png"
prev.save(pv)
print(f"已存：{a.out}；接缝预览：{pv}")
```
